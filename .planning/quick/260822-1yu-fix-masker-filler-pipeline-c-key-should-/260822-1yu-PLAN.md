<objective>
Fix the masker/filler pipeline so C works on text-only pages and add a standalone filler.

Root cause diagnosis (verified against source):
1. `MainWindow._refresh_action_states` (main_window.py:1237-1241) enables `action_inpaint` ONLY when
   `canvas.has_mask_content()` — i.e. the composite mask has painted pixels. On a page where every box
   has std_dev <= threshold ("std dev 0"), all boxes route to the FILL plane, `compose_auto_binary`
   returns an empty binary, the composite mask is empty → **C stays disabled** → "pressing C never runs
   the masker". Forcing the sidebar override to "always" makes the box contribute to the auto plane →
   C becomes enabled and LaMa inpaints — exactly the unwanted behavior the user observed.
2. The one-shot worker (`_run_inpaint_task`, main_window.py:5140) ALREADY does fill-then-inpaint
   correctly for std<=threshold boxes (`compose_fill_specs`) — it is just unreachable on fill-only pages
   because of the gate in (1).
3. There is no UI action that runs only the filler.

Purpose: text-only manga pages (all-flat bubbles) currently cannot be cleaned at all from the GUI.
Output: C enabled/functonal on fill-only pages; new Tools > "Fill Boxes" (F) standalone filler; tests.
</objective>
