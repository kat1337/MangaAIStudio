# Quick Task 260907-m4u — Ctrl+click a bubble with the Move tool (V) copies its detected text

**User ask (paraphrased):** not a new toolbar tool — a modifier-key interaction: while the Move tool (V) is active, Ctrl+click on a bubble copies that bubble's detected (OCR) text to the OS clipboard.

## Current behavior (evidence, file:line from working tree)

## Design

**Canvas extracts, MainWindow copies.** One new signal `copy_text_requested = Signal(str)` on EditorCanvas. The dispatch branch (inside `isinstance(item, BoxItem)`, BEFORE the Shift check — Ctrl wins over Shift on a Move-tool box press) is gated on `self.current_tool == ToolMode.MOVE` AND `event.modifiers() & Qt.KeyboardModifier.ControlModifier`. On hit: select the box without arming a drag (`if not item.isSelected(): self._deselect_box(); item.setSelected(True)`), emit `copy_text_requested(detected_text(item.pagebox))`, `event.accept()`, `return`. The signal carries the text even when empty (canvas stays dumb; MainWindow decides the empty feedback). A CornerHandle/RotationHandle hit is a resize/rotate gesture, NOT a copy — the branch only fires on the BoxItem arm, exactly like today's select+move arm.

**`detected_text(pb)`** in text_renderer.py beside `current_focus_text` (:285): the recognized text ONLY — same defensive shape, but reads `payload.text` and never falls back to `translation`. Reason: the user's words are "the detected text" — the OCR layer's output (what a scanlator pastes into a translator), not the D-04 display-focus text.

**MainWindow handler** `_on_box_text_copy_requested(text: str)` mirrors `_on_ocr_grab_finished` (:7362) verbatim in structure (empty-rule, clipboard write, transient copy), connected beside the other canvas signal connections at main_window.py:164. Docstring records the deliberate OS-clipboard carve-out per :7366-7368.

**Discoverability:** the Move tool tooltip (`tools_strip.py:130`, `"Move/Pan tool (V)"`) gains " — Ctrl+click a bubble to copy its detected text." — one string, matches the strip's established tooltip-clause pattern (the brush family's Alt clause at :136-137).

**Strictly out of scope:** Ctrl+click on other tools (CROP/OCR_GRAB keep today's behavior; paint tools keep Alt-only per MASK-06), a toolbar/menu entry for the feature (user explicitly rejected a new tool), copying the translation instead, multi-box copies.
