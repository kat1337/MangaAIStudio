# Quick Task 260909-ke1 — Stability: file logging + crash/freeze diagnostics; investigate paste-after-delete freeze

**User ask (verbatim, authoritative):**

"i've been having some issues and unstabilities lately, specifically i copied the text in a box, deleted the box, expanded a different box and pasted, the app then froze and stop, it's kind of really hard to debug these issues because there are no logs"

Two deliverables: (1) file logging + crash capture + hang capture + Qt message routing so freezes/crashes are debuggable; (2) investigate the specific repro, fix only what is demonstrably wrong — do NOT speculatively refactor.

## Diagnosis (source-traced on this codebase — every reference below verified, not guessed)

**Deliverable 1 — there is no diagnostics infrastructure at all:**
- Entrypoint `manga_ai_studio/__main__.py` (`main()`, lines 21-42): `create_app(sys.argv)` -> `ProfileManager(Path.home() / ".manga_ai_studio")` -> `MainWindow` -> `app.exec()`. The ONLY logging statement is `logger.exception(...)` at line 38, and loguru has **zero sinks configured** — every `logger.*` call in the app (core + gui: `detection_boxes.py:91`, `batch_runner.py:368-395`, `project_io.py:516`, `ocr_export.py:390,488`, `main_window.py:2118-3207`, `text_renderer.py:1183`, `load_translations_dialog.py:176`) goes to loguru's default STDERR sink and dies with the console. No file sink, no rotation, nothing on disk.
- No `sys.excepthook`, no `threading.excepthook`, no `faulthandler`, no `qInstallMessageHandler` anywhere in the package (greps return empty). An exception in a Qt slot and a main-thread wedge are both completely invisible today — exactly the user's complaint.
- Versions (measured): PySide6 6.10.1, loguru 0.7.3, Python 3.14.2 (the AGENTS.md pinned interpreter). PySide6 6.10 routes unhandled slot exceptions to `sys.excepthook`, so installing the hook captures the slot-crash path; the plan's Task 2 test proves this on the installed version rather than trusting the changelog.
- Natural log home: `~/.manga_ai_studio/` already exists at `__main__.py:25-26` (profiles + config.ini live there) — `logs/` beside it needs no new user-facing concept. App version: `manga_ai_studio/__init__.py` `__version__ = "0.1.0"`.

**Deliverable 2 — the repro's code paths, traced:**
- *Copy text*: Ctrl+click under the Move tool (canvas.py:1660-1669) emits `copy_text_requested(detected_text(item.pagebox))` -> `MainWindow._on_box_text_copy_requested` (main_window.py:7588) writes the OS clipboard. Plain TEXT crosses the boundary — no scene-object references. NOT a stale-reference suspect.
- *Copy boxes*: Ctrl+C -> `_copy_selected_boxes` (canvas.py:3356-3368) fills `box_clipboard` (canvas.py:385) with detached `PageBox.copy()` clones — in-process Python state, no scene refs. NOT a stale-reference suspect either.
- *Delete box*: Delete/Backspace branch (canvas.py:2386-2409) -> `_remove_box` (canvas.py:3486-3506) or the multi-delete branch -> `_retire_boxes` graveyard (canvas.py:2621-2654): removed BoxItems are held then released via `QTimer.singleShot(0, _release_graveyard)` because dropping the last Python ref mid-event-loop deletes the C++ item while paint events may still reference its overlay children (the documented teardown-UAF family, G-07-6).
- **DEFECT CANDIDATE 1 (demonstrable staleness violation):** the Delete branches and `_remove_box` have **no inline-editor guard**. `set_boxes` commits the active editor before any layer rebuild (canvas.py:2675, `_commit_inline_editor_if_active` at 2977-2986) precisely so "a stale editor never dangles over a removed box" — but deleting a box via the keyboard (the reported repro!) skips that seam entirely. If the editor is open on box A (the user was just reading/copying its text) when A is deleted: `InlineEditor._active_box_item` keeps pointing at the retired item, the graveyard may release its C++ object on the next loop iteration, and the editor's later `commit()` -> `box_item.refresh_text_overlay()` (inline_editor.py:244) / `set_edit_mode` teardown (inline_editor.py:291) raises `RuntimeError: Internal C++ object already deleted` inside a slot — PySide6 slot exceptions can abort or wedge the event loop silently (the reported signature: freeze, no dialog, no logs). Fixable deterministically and headlessly testable.
- *Expand box B*: resize drag (`_begin_resize` -> mouseMoveEvent -> release commit) emits `boxes_modified` -> MainWindow undo/dirty/geometry-stale marking. Per quick-260824-pqn there is NO automatic re-detect on this path.
- *Paste*: Ctrl+V (canvas.py:2492-2499) -> `_paste_boxes` (canvas.py:3370-3424); an empty `box_clipboard` is a silent no-op, so this path only runs if boxes were Ctrl+C'd earlier. With the inline editor active, Ctrl+V goes to the editor instead (canvas.py:2496 guard) and is stock `QTextEdit` paste (`_EditorTextEdit`, inline_editor.py:99-114) — nothing listens to `textChanged`, commit happens on Enter/click-away only.
- **DEFECT CANDIDATE 2 (noted, NOT tasked):** `_paste_boxes` page clamp (canvas.py:3397-3401) — when the clipboard box is wider/taller than the page, `max(0, page_w - w)` collapses the origin to 0 but keeps `w`, producing an out-of-page rect that contradicts the "Clamp the pasted rect inside the page" comment. Not reachable from the reported repro (the pasted box is source-box-sized); record it in the SUMMARY, do not fix it here.
- **Ruled out as top suspects:** the overlay auto-fit loops are bounded (grow capped at `min(inner_w, inner_h)` + shrink budget + 5px floor — text_renderer.py:691-717 horizontal/vertical at 805-849), and the historical freeze family (260822-vk7, 260826-vhh) was already fixed there. Clipboard/undo snapshots are detached (`PageBox.copy()` discipline). The honest position: the exact freeze is not statically provable; the diagnostics deliverable is what makes the NEXT occurrence self-reporting, and Task 3's harness proves/disproves the demonstrable candidate.

## Design

**Diagnostics module** (`manga_ai_studio/diagnostics.py`, stdlib + loguru only at module level — PySide6 imported lazily so the core unit tests run without Qt):
- `install(base_dir=None) -> Path`: log dir = `base_dir` or `Path.home() / ".manga_ai_studio" / "logs"`. ONE rotating loguru file sink `mas.log` (rotation="5 MB", retention=3, encoding="utf-8", enqueue=True so a slow disk write can never stall the GUI thread — this is a stability tool). Filter function admits a record when: level >= WARNING, OR the record name starts with `manga_ai_studio.gui` (DEBUG floor for gui/canvas), OR `record["extra"].get("session_marker")` (lets the INFO session separator survive the WARNING floor). Timestamped format with module:function:line. Idempotent via a module flag; `reset()` (sinks removed, hooks restored, flag cleared) exists ONLY for tests.
- Crash capture: `sys.excepthook` and `threading.excepthook` are wrapped — log the traceback via loguru ERROR, then call the previous hook (never swallow). PySide6 6.10 delivers slot exceptions to `sys.excepthook`, so this one hook covers CLI + slot paths.
- Hang capture: keep module-level handles to `mas-hang.log` (separate file from the loguru sink — faulthandler writes raw from its watchdog thread; same-file sharing with loguru's appender risks interleaving on Windows). `faulthandler.enable(file=hang_fh)` + `faulthandler.dump_traceback_later(timeout=60.0, repeat=True, file=hang_fh)` — the watchdog THREAD dumps ALL thread stacks when the main thread misses its deadline; it works precisely because it does not need the frozen main thread's cooperation. `heartbeat(app, interval_s=15.0)` arms a QTimer parented to the QApplication whose tick calls `faulthandler.cancel_dump_traceback_later()` then re-arms `dump_traceback_later` — a live loop resets the deadline forever; a wedged loop stops ticking and the dump fires ~60s in (the user-reported "froze and stop" becomes a stack trace naming the stuck slot). Expected long operations do NOT need special handling: model inference runs on the Worker thread (main loop keeps ticking); any >60s MAIN-thread stall is by definition a freeze worth dumping.
- Qt routing: `install_qt_message_handler()` wraps `qInstallMessageHandler` mapping QtDebugMsg->DEBUG, QtInfoMsg->INFO, QtWarningMsg->WARNING, QtCriticalMsg->ERROR, QtFatalMsg->CRITICAL, including the context (file/line/function).
- Session separator: on install, `logger.bind(session_marker=True).info(...)` with app version, ISO timestamp, platform + python version; `__main__` also `print(f"[manga-ai-studio] log file: {path}", file=sys.stderr)` so the user can always find it.

**Freeze investigation**: a headless repro harness (pytest-qt, `@pytest.mark.gui`) scripts the exact reported sequence twice — as-reported, and the stale-editor variant — asserting invariants instead of wall-clock hangs (no pytest-timeout in this project; a "wait for a hang" test would hang CI). Where the harness demonstrates the staleness defect, the delete path gets the commit-first guard mirroring set_boxes. Plus ~8 one-line `logger.debug` breadcrumbs along the traced paths so the user's next repro produces a readable trace in the file.
