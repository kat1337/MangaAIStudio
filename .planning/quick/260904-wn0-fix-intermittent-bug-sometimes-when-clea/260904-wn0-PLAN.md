# Quick Task 260904-wn0 — Fix intermittent flat-white corner fill when cleaning (C) after resizing a box

**Symptom:** Sometimes pressing C paints a flat white patch (not LaMa) at the upper-left corner of a box; user must repair with O (restore). Suspected trigger: resize a box, then C. **Confirmed by code read.**

## Root cause (evidence, file:line from working tree)

1. **Fit data is anchored to fit-time geometry.** `_fit_one_box` (`manga_ai_studio/core/detection_boxes.py:369-390`) stores `pb.mask` cropped EXACTLY to the fit-time box (`ops.cut_out_mask` to `pb.box` translated into reference coords — so the invariant `mask.size == (box_w, box_h)` holds at fit time), plus fit-time `pb.std_dev` and `pb.fill_color`.
2. **Resize commits nothing to fit data.** `Canvas._commit_resize` (`manga_ai_studio/gui/canvas.py:2936-2963`) only clamps the rect, syncs handles, refreshes the overlay, emits `boxes_modified`. `Canvas.boxes_snapshot()` (`canvas.py:2603-2622`) builds PageBoxes with CURRENT geometry (`item.current_box()`) but forwards the FIT-TIME `mask` / `std_dev` / `fill_color` verbatim from the live pagebox.
3. **The fill pass pastes the fit-time mask at the CURRENT box origin.** `compose_fill_specs` (`detection_boxes.py:498`) returns `(pb.mask, pb.fill_color, (pb.box.x1, pb.box.y1))`; the worker alpha-composites there (`main_window.py:6315-6319`). After a resize that moved the box origin (any handle except bottom-right), the old mask lands offset from the actual text → flat median-color (commonly white) patch near a corner. Because `std_dev <= threshold` still routes the box to FILL, LaMa never runs — exactly the reported "flat white, NOT LaMa".
4. **Same stale-mask-at-current-origin paste exists in `compose_auto_binary` (`detection_boxes.py:434`) and `compose_fill_binary` (`:468`)** — a resized box misinpaints/mis-bboxes too. The worker's inline `auto_contrib` count loop (`main_window.py:6281-6289`) mirrors the old predicate.
5. **The system already has the authoritative staleness invariant — only at the persistence boundary.** `project_io.py:254-276` (quick-260825-u9q): `mask_stale = pb.mask is not None and pb.mask.size != (box_w, box_h)` → save nulls mask + std_dev + fill_color. The in-session compose path never applies this check — that is the whole bug.

## Fix design (lift the persistence rule into the live path — skip, do not substitute)

Treat a box whose stored mask dims no longer match its current box dims as carrying stale fit data: it contributes NOTHING to fill or LaMa — identical to `gate_skipped` semantics, and identical to its own post-save/reload state (save nulls the stale data, so after reload the box is already gate_skipped). Re-derivation path already exists: the amber geometry-stale per-box re-detect affordance (quick-260822-gnq). This satisfies the lead's "never flat-white-filled from stale state; re-derived correctly" branch without overriding user per-box intent (no silent rect-LaMa substitution, no forced_fill violation).

**Deliberately out of scope:** rect-substitution LaMa routing for stale boxes; new UI state strings; changing pure-MOVE behavior (dims unchanged → mask still fresh → unchanged behavior, regression-guarded); `inpaint_state` vocabulary changes beyond what falls out of the predicate; batch_runner changes (it calls the same compose functions at `batch_runner.py:296` and inherits the fix).
