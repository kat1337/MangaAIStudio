# Quick Task 260909-fa9 — Fix textbox overlay bugs: zoom-adaptive border, corner-anchored handles/buttons, arrow-key nudging

**User ask (verbatim, authoritative):**

1. **Zoom-adaptive textbox border thickness.** When the canvas is zoomed out, textbox outlines are sometimes too thin to really see. Border stroke thickness must scale with zoom so it stays clearly visible when zoomed out and thinner when zoomed in (i.e., roughly constant *minimum* on-screen thickness).
2. **Corner handles + angle/re-detect buttons drift off the box.** They must be anchored exactly to the corners/edges of the box at every zoom level and box size.
3. **Arrow-key nudging with the V (select) tool.** A selected textbox moves 1px per arrow press (image/document pixels); holding the key keeps moving it (key repeat).

## Diagnosis (probe-verified on this machine — numbers below are measured, not theorized)

A live probe rendered the real `EditorCanvas` + `BoxItem` at five zooms and measured pixels (`viewport().grab()`):

- **Root cause of BUG-2 (drift):** the decorations are `ItemIgnoresTransformations` children — their CONTENT is fixed viewport px (8x8 handle, 10x10 circles, digit-sized badge), but `reposition` anchors them with fixed SCENE-unit offsets (`corner - 4`, `top - 18 - 5`, `right + 2`). The anchor scales with zoom while the content doesn't, so the visible center lands at `corner + offset*(1 - zoom)` device px. Measured TL-handle center drift: **0 px at 1.0x, +2 at 0.5x, +3 at 0.25x, -4 at 2.0x, -12 at 4.0x** — exactly `4(1-z)`. Measured rotation-handle drift at 2.0x: `(-5.5, -23.5)`. A second drift path: `_register_box_item` (canvas.py:2641) never seeds the canvas zoom into new BoxItems, so boxes created at fit-to-window zoom (e.g. 0.18 on a large page) carry `_overlay_zoom = 1.0` until the next zoom change.
- **Root cause of BUG-1 (thin border):** the border pen width is fixed SCENE px (`_UNSELECTED_PEN_WIDTH = 2` / `_SELECTED_PEN_WIDTH = 3`, box_item.py:99-100) so on-screen thickness = base * zoom. Measured: **0 exact-color border pixels** along a 50px top-edge run at zoom 0.25 and 0.5 (effectively invisible), 200+ at zoom >= 2.
- **BUG-3 (nudge):** nothing consumes arrow keys anywhere (`grep Key_Left/Right/Up/Down` over gui/ → no hits); `EditorCanvas.keyPressEvent` (canvas.py:2356) is the natural home and already handles Delete/Esc/F2/Ctrl+C/Ctrl+V for boxes.

Zoom is a real view transform (`zoom()`/`zoom_reset()`/`fit_to_window()` all call `setTransform(QTransform().scale(...))` and emit `zoom_changed`, canvas.py:1439-1499; every zoom path emits — `suppress_signals=True` has no callers), so `ItemIgnoresTransformations` position anchoring through the device transform is correct; only the offset math and the missing seeding are wrong.

## Design

- **Pen:** new module helper `_zoom_pen_width(base, zoom)` in box_item.py returning `base / zoom` (zoom guarded to 1.0 when non-positive/non-numeric, capped at a 24 scene-px degenerate bound) — on-screen thickness becomes exactly `base` viewport px at every zoom (visible when zoomed out, proportionally thinner on screen than today when zoomed in). The dash pattern `_INPAINT_DASH_PATTERN` stays UNCHANGED: Qt dash units are multiples of the pen width, so the rendered dash automatically rides the compensated width.
- **Anchoring:** every device-px offset is divided by the live zoom when converted to a scene-unit `setPos` (handle half-size 4, rotation 18+5, re-detect 10+2, badge size+offset). `_handle_hit_rect`'s center moves to local `(4/zoom, 4/zoom)` so the scene-space hit center stays on the true corner. All formulas reduce to today's exact values at zoom 1.0.
- **Nudge:** arrow keys under `ToolMode.MOVE` translate every selected box rect by 1 scene px + `_sync_handles` (the group-move reposition-only discipline). A `_nudge_before` snapshot opened on first press and flushed as ONE `boxes_modified` emission on the (non-auto-repeat) key release gives one undo entry per burst; missed-release safety nets flush on any other key release, any mouse press, and `set_boxes`.
