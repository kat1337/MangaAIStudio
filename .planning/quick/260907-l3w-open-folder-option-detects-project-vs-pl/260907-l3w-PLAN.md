# Quick Task 260907-l3w — Open Folder detects project vs plain folder

**User ask (paraphrased):** the Open Folder option should tell whether the folder being opened is full of images or is/contains a Manga AI Studio project — if it's a project or contains one, load the project; otherwise just load the images / .mas files in the folder.

## Current behavior (evidence, file:line from working tree)

1. `open_folder` (`manga_ai_studio/gui/main_window.py:2018`): directory dialog → `_confirm_discard_changes()` → `_load_folder(Path(directory))`. No project detection of any kind.
2. `_load_folder` (:2033): flat non-recursive scan of `p.is_file() and validate_image_path(p)` → `_set_pages(candidates)`. Only images. A project folder opened here yields "No images found in folder" (manifest.json/.mas are not images) even though it IS a project.
3. Project loading exists and is battle-tested: `_load_project_session(manifest_path)` (:3509) rebuilds the full session and runs the D-07 Unsaved Changes gate itself, exactly once; `_open_project` (:3153) shows the corrupt-project `QMessageBox.critical` copy on `(ProjectFormatError, OSError)` and never mutates the current session.
4. `project_io.find_sibling_manifest` (`manga_ai_studio/core/project_io.py:863`) establishes the validation precedent: manifest exists AND `load_project` succeeds → valid; manifest exists but malformed → **raise** `ProjectFormatError` (never silently degrade).
5. `_on_folder_dropped` (:2445) shares `_load_folder`; `_set_pages` (:2045) is the image-session swap; `_build_image_file_from_parsed` (:3299) builds a full `ImageFile` from parsed .mas entries (used by both project-session loaders); `_display_page_state` (:3383) displays a page from its embedded state.

## Design

**Detection order for an opened folder** (new pure helper `project_io.find_project_manifest(directory)`):
1. `directory / "manifest.json"` exists → validate with `load_project` → return it (folder IS a project); malformed → raise `ProjectFormatError` (find_sibling_manifest precedent — a corrupt project must never fall through to the image route).
2. Else immediate subdirectories (natsorted by path, deterministic first-wins): first `sub / "manifest.json"` that exists → validate → return it (folder CONTAINS a project); malformed → raise.
3. Else return `None` (plain folder → images + .mas route). Non-directory input returns `None`.

**Routing** (new `MainWindow._open_folder_session(directory)`, the single router):
- `find_project_manifest` → on `(ProjectFormatError, OSError)`: loguru error + the same corrupt-project `QMessageBox.critical` copy `_open_project` uses (:3206-3211); session untouched; return.
- Manifest found → `self._load_project_session(manifest)` (its internal D-07 gate is the one and only gate on this route).
- Manifest `None` → `_confirm_discard_changes()` (the one and only gate on this route) → `_load_folder(directory)` wrapped in `try/except (ProjectFormatError, OSError)` with the same corrupt-project dialog (Task 3 makes .mas loading able to raise).
- `open_folder` slims to: dialog → `_open_folder_session(Path(directory))`. `_on_folder_dropped` reroutes to `_open_folder_session(directory)` so dropped folders get identical detection (deliberate: folder drops also gain the D-07 gate on the plain-folder route — consistent with the gate's data-loss-prevention purpose; file drops `_on_files_dropped` stay untouched).

**.mas pages in a plain folder** (`_load_folder` extension): also collect flat `p.suffix.lower() == ".mas"` files. If there are none → `_set_pages(image_candidates)` exactly as today (zero risk to the ~10 existing `_load_folder` call sites). If any exist → build EVERY page's `ImageFile` BEFORE swapping (image-backed: `ImageFile(path=p, original_verified=True)`; .mas-backed: `load_page_file` + `parse_page_entries` + `_build_image_file_from_parsed(parsed, mas_path)`), any `ProjectFormatError` propagates to the router's dialog (all-or-nothing: session untouched). Combined list natsorted by `str(imf.path)`, then the swap mirrors `_load_project_session`'s tail with folder identity (`_project_dir = None`, `_project_name = None`, `dirty = False` all pages): `_session_generation += 1`, `_last_page_index = None`, `file_table.set_pages(...)`, `select_path(first.path)`, then first-page display — `_display_page_state(first)` + `reset_history()` when `first.current_image is not None` (.mas-backed), else `on_page_selected(first.path)` (image-backed lazy load). Empty combined list keeps today's "No images found in folder" status.

**Deliberately out of scope:** recursive project search (immediate subdirectories only — one level, matching the user's "contains one"); recursive image scan (flat scan is the UI-SPEC surface 4 contract); picking among MULTIPLE project subdirectories interactively (deterministic natsorted-first; documented in the docstring); any Recent Projects mutation on the folder route (project-route `_load_project_session` behavior is unchanged and already records recents via its own callers... actually `_add_recent_project` is called by `_save_project`/open flows, not `_load_project_session` — leave that machinery exactly as is).
