<investigation_findings>
Probe-confirmed root causes (planner investigation, 2026-08-24):

1. **Editor font**: `InlineEditor.__init__` hardcodes `font-size: 14px` in a stylesheet (inline_editor.py:136). The `QGraphicsProxyWidget` does NOT ignore transformations, so the 14px font scales WITH the view transform: at 25% zoom the editor text renders at ~3.5 screen px. The proxy is parented to the SCENE and positioned/sized in scene coords off `sceneBoundingRect()` (enter(), lines 181-186), which also shrinks with zoom — but the reported pain is the FONT, so the fix compensates font size inversely to zoom (scene px = base/zoom), the exact pattern precedent from Phase 4 plan 04-08 ("clamp(14*zoom,10,28)/zoom scene px").

2. **Handle hit area**: `CornerHandle.shape()`/`boundingRect()` return a fixed `_HANDLE_HIT_SIZE = 18` rect in LOCAL units (box_item.py:122, 258-384). The canvas hit-test queries `QGraphicsScene.items(scene_pos, ..., QTransform())` with an IDENTITY transform (canvas.py:2426-2431). So the 18-unit grab zone is in SCENE px: at zoom z its effective screen size is 18*z viewport px — only 4.5 px at 25% zoom. That is why grabbing degrades when zoomed out. Fix: divide the hit rect by the current zoom so it stays constant in VIEWPORT px. The parent `BoxItem` already stores the live zoom in `_overlay_zoom` (updated by `apply_overlay_zoom` on every `zoom_changed` emission, canvas.py:1790 slot covers wheel/reset/fit-to-window/page-load default).

   Bottom-left asymmetry: NO code-level asymmetry found — the badge sits TL-OUTSIDE and the redetect affordance TR-OUTSIDE, both explicitly placed to avoid their handles' hit zones (box_item.py:163-165, 179-181); the hit-test iterates z-descending so the handle (z=150) beats the box body (z=100) everywhere. Likely cause of "especially bottom-left": at low zoom the whole 4.5px zone vanishes and the user notices it on the corner they drag toward most (bottom-left, right-handed pull-down-left). Task 2 includes a probe assertion; if a real asymmetry surfaces during execution, document it in the summary and widen that corner's zone specifically.

3. **Live size rendering**: the Size QSpinBox commits ONLY via `editingFinished` (inspector_panel.py:1229-1231) — Qt fires that on focus-loss/Enter, not per click of the up/down arrows or scroll wheel. Fix: ALSO connect `valueChanged` through a short debounce timer to the same `_emit_style_size_if_changed(on_style_size)` emitter. All programmatic loads wrap mutations in `blockSignals(True)` (lines 778, 902, 1066), so no spurious commits; the WR-01 loaded-value no-op guard inside the emitter prevents redundant pushes.
</investigation_findings>
