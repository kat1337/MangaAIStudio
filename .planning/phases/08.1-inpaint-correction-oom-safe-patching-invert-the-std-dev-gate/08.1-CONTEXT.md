# Phase 08.1: Inpaint correction & OOM-safe patching - Context

**Gathered:** 2026-08-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Correct the std-deviation text-removal semantics to match PanelCleaner and make inpainting memory-safe on large pages.

**In scope:**
- Invert the gate so uniform (low-std) boxes get a median-color **fill** and complex (high-std) boxes get **LaMa inpainting** (Phase 8 had this inverted: it AI-inpainted uniform boxes and skipped complex ones).
- One combined "Inpaint" action that performs the fill + the LaMa pass in a single shot with a single undo entry.
- Re-map the Inspector override to four states: Auto / Fill / Inpaint / Never.
- Patch-based OOM-safe inpainting: cap the LaMa input size, crop patches around masked regions, and defer edge-straddling masks to later patches.
- Batch Detect+Clean / Batch Clean adopt the same corrected gate and patched inpainting.

**Out of scope:**
- Mask grow/shrink brush (MASK-04, v2).
- Per-region LaMa parameters (FLOW-07, v2).
- OCR crop geometry fix (IN-01 from 08 review) — separate follow-up.
- Any UI rework / panel restructuring (Phase 9).

</domain>

<decisions>
## Implementation Decisions

### Gate semantics (PanelCleaner correction)
- **D-01:** The std-dev gate is INVERTED relative to Phase 8: a box is AI-inpainted (LaMa) when its border std dev is ABOVE the threshold (complex/uniform-to-the-model region); a box is median-color FILLED when its border std dev is at or BELOW the threshold (uniform region). This matches `panelcleaner/image_ops.py:705` (`pick_best_mask` fails above `mask_max_standard_deviation` → inpaint path; succeeds below → mask/fill path) and `panelcleaner/config.py:828-900` (Inpainter section).
- **D-02:** The threshold remains the existing `mask_max_standard_deviation` (default 15) surfaced by the same "Std dev threshold" control; only the side of the gate that each behavior applies to is swapped. Hand-painted (manual plane) strokes are ALWAYS inpainted regardless of the gate (unchanged contract).

### Combined Inpaint action
- **D-03:** The Inpaint (C) action does both passes in one flow: (1) median-color fill of every Auto/Fill low-std box text-mask, (2) LaMa inpainting of the composite of (a) high-std Auto boxes, (b) Inpaint-override boxes, (c) manual-plane strokes, minus erase. Both results are baked into the page image as ONE undo entry (like today's Inpaint). Fill is not live at detect/recompute time — it applies at Inpaint time.

### Override semantics (4 states)
- **D-04:** Inferooverride vocabulary becomes four values, persisted in `.mas` as `inpaint_override`:
  - `none`/absent = **Auto** — fill if std ≤ threshold, inpaint if std > threshold
  - `fill` — force the median-color fill regardless of std (even on a complex box; user's explicit choice)
  - `always` — force LaMa inpainting regardless of std (even on a uniform box)
  - `never` — leave the text entirely (no fill, no inpaint)
  The Inspector combo becomes Auto / Fill / Inpaint / Never (replacing Auto / Always / Never) with the existing Mixed sentinel for multi-select. The `"fill"` value is new — `.mas` load/save, save-loop emission, and the compose/fill split must all handle it. Legacy files with only the old vocabulary load unchanged.

### Memory-safe patching (OOM guard)
- **D-05:** Max LaMa input size is a user setting (UI input box in settings/preferences, saved in the profile/INI) with a default of **2048×2048** pixels. If the whole page fits within the max size, the whole page is passed to LaMa (no patching).
- **D-06:** For larger pages, build patches around the regions to inpaint: each patch is the mask bbox grown to at least 25% of the image (per side), with a ~10% margin around the mask on every side that has room, capped at the max size.
- **D-07 (edge refinement):** The 10% margin applies ONLY where the image has space — a mask at the page edge gets the patch clamped to the page boundary on that side (no margin there; mask fully included, never deferred for edge proximity).
- **D-08:** A mask whose bbox crosses a patch edge in the INTERIOR (non-page-edge) case is excluded from the current patch and collected into a deferred list; subsequent patches are built around the deferred masks until every mask is covered. Each patch is inpainted independently and composited onto the page; the run produces ONE undo entry.
- **D-09:** Batch Detect+Clean and Batch Clean adopt the same corrected gate and the same patched inpainting (consistency with interactive quality; this closes the Phase 8 UAT item on batch quality matching interactive).

### Claude's Discretion
- Border pattern/color mapping for the 5 visible states (will-fill Auto / will-inpaint Auto / forced-fill / forced-inpaint / never) — keep the existing 4-pen system, extend the dash/grey palette minimally to distinguish fill from inpaint.
- Patch progress reporting ("{patch} of {N}" in the status bar).
- Exact patch composition/border handling implementation detail (crop/paste round-trip between numpy/QImage bridges).

</decisions>

<specifics>
## Specific Ideas

- "This is how PanelCleaner does it": uniform box → mask (fill with median color), complex box → inpaint with the AI model. The Phase 8 success criteria ("preserving complex artwork instead of inpainting whole boxes") misread the gate direction — the fix is to AI-inpaint the text region in complex boxes (regenerating just the text, never the whole box), and cheap-fill the uniform ones.
- Max inpainting size saved in preferences (profile INI), default 2048×2048, UI input box.
- Patch margin: ≥25% of image per side, ~10% margin around the mask where the image has room; page-edge masks are clamped to the edge (no margin that side).
- Interior edge-straddling masks are deferred to the next patch until covered.
- One undo entry per Inpaint run, even across multiple patches.

</specifics>
