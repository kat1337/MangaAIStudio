## Origin

User reported that the Phase 8 std-deviation/inpainting semantics may be misunderstood and requested a change to inpainting for large images. Verified against the vendored code (`panelcleaner/image_ops.py:705` — `pick_best_mask` fails above `mask_max_standard_deviation` → inpaint path) and the upstream PanelCleaner config (`panelcleaner/config.py:828-900` Inpainter section).

**Confirmed misunderstanding:** Phase 8's `compose_auto_binary` includes a box's text-mask in the auto plane only when `std_dev <= threshold` (uniform) → the app's single Inpaint operation LaMa-inpainted uniform boxes and SKIPPED complex ones. PanelCleaner's actual model: uniform boxes get a cheap median-color fill; complex boxes get the AI (LaMa) inpaint — because regenerating text on a complex background is the only way to remove it, while uniform backgrounds just need a color fill.

## Inpaint action behavior

| Option | Description | Selected |
|--------|-------------|----------|
| One combined action | The Inpaint (C) action does both passes in one flow: median-fill low-std boxes + LaMa high-std + hand-painted strokes, one undo entry. Mirrors PanelCleaner's clean pipeline. | ✓ |
| Two separate actions | Separate "Mask fill" (median color) and "Inpaint" (LaMa) actions; user chooses. | |

**User's choice:** One combined action
**Notes:** Also chose one-shot, one undo entry (fill is not live at detect/recompute; it applies at Inpaint time).

## Override semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Always=force LaMa, Never=leave, Auto=std-based | Always forces AI inpaint even on uniform; Never leaves text; Auto uses the std gate. | ✓ (with vocabulary change) |
| Always=best method for that box | Explicit intent flag whose outcome equals Auto. | |
| Add a 4th "Fill only" override state | A state for explicit fill even on a complex box. | ✓ (incorporated) |

**User's choice:** Change the verbiage to four states: Never / Auto / Fill / Inpaint
**Notes:** Auto = fill if uniform / inpaint if complex; Fill = force median fill regardless of std; Inpaint = force LaMa regardless of std; Never = leave text. `.mas` vocabulary gains `"fill"` alongside `"always"`/`"never"`.

## Memory-safe patching config

| Option | Description | Selected |
|--------|-------------|----------|
| Max 2048×2048 | Safe on most hardware via ONNX; whole page passed when it fits. | (default) |
| Max 3072×3072 | Higher context, higher VRAM/RAM. | |
| Configurable, default 2048×2048 | User setting, UI input box, saved in preferences. | ✓ |
| Patch 25%-of-image, 10% side margin | Patch = mask bbox grown to ≥25% of image per side, ~10% margin, capped at max. | ✓ |
| Fixed 256px padding | Simple, less context. | |
| Downscale whole page | Single pass, quality loss risk. | |
| Defer + later patch | Edge-straddling masks collected and re-patched until covered. | ✓ |
| Clip partial masks into current patch | Simpler, artifact risk. | |

**User's choice:** Configurable max (default 2048×2048), 25%-of-image patch with ~10% side margin, defer + later patch.
**Notes:** Edge refinement — the ~10% margin only applies where the image has room; a mask at the page edge gets the patch clamped to the boundary (no margin that side, mask fully included, never deferred for edge proximity). Batch Detect+Clean and Batch Clean adopt the corrected gate + patched inpainting. Undo = one entry per run, even across multiple patches.
