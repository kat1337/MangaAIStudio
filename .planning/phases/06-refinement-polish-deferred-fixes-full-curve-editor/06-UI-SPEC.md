## Spacing Scale

Inherited unchanged from Phase 1 (4 / 8 / 16 / 24 / 32 / 48 / 64). Phase 6 adds **no** new layout spacing tokens. Dialog rhythm follows the inherited form rhythm: `QFormLayout` row spacing `sm` (8px), root `QVBoxLayout` spacing `sm` (8px), **new Curves dialog contents margins `md` (16px)** (the 05-UI-SPEC §Spacing row declares 16px dialog margins; the new dialog sets them explicitly — the existing three dialogs' inherited ~9–11px default is NOT in D-12 scope and stays untouched), preset/In-Out rows gap `md` (16px).

**Phase 6 exceptions (non-spacing geometric/interaction values, declared here so they are not "invented" later — same discipline as Phase 5's crop values):**

| Value | Usage | Rationale |
|-------|-------|-----------|
| **256 × 256 units** | CurveWidget grid input/output space (x = input 0…255, y = output 0…255) | The Photoshop/GIMP curves convention; every point coordinate lives in [0,255]² |
| **64 / 16 unit** | Major / minor gridline intervals (a 4×4 major + 16×16 minor subdivision of the 256-unit grid) | GIMP curves convention; major lines read at a glance, minor lines give precision context |
| **10 px** | Point hit-test radius (`mousePressEvent` — click selects/drags a point within 10px, else adds a new point) | RESEARCH Pattern 3 hit-test ~10px; comfortably larger than the 8px visual handle (usability), consistent with Phase 3's enlarged-corner-handle discipline |
| **8 × 8 px** | Interior control-point handle visual size (unselected: `#e8e8ea` fill, 1px `#3a3a42` border; selected: 2px accent `#00d4ff` outline) | Mirrors the Phase 3 corner-handle 8×8 size verbatim — the app's established handle grammar |
| **10 × 10 px** | Endpoint handle size (the fixed (0,0)/(255,255) anchors) — visually distinct from interior points so "fixed, edge-draggable" reads at a glance | Endpoints are special (D-04: never deletable, y-only movement); size difference signals it |
| **2 px** | Curve line width (accent `#00d4ff`) | Matches the inherited 2px preview/crop border pen family (Phase 5 declared exception) |
| **1 px** | CurveWidget plot-area border (`#3a3a42`) and major gridline width; minor gridlines 1px at reduced alpha | Declared token usage, no new colors |
| **±1 / ±10** | Arrow-key point nudge (D-07): plain arrows move the selected point 1 unit, Shift+arrows 10 units | Locked D-07 keyboard story (Photoshop convention) |
| **280 × 240 px** | CurveWidget minimum size (`setMinimumSize(280, 240)`); the plot square = largest square that fits the widget minus an 8px margin on each side | RESEARCH Common Operation 3 skeleton; a square plot keeps the 256-unit grid undistorted |
| **0.14 alpha** | Histogram fill `rgba(232, 232, 234, 0.14)` (text-primary at 14%) — the D-08 "faint histogram" behind the grid | Faint enough to never compete with the curve line, light enough to read the page's tonal distribution |
| **0.10…4.00 / 1.00** | Gamma range / default (inherited from Levels, D-03 — the gamma control is kept) | Locked D-03; log-scaled slider mapping reused from `levels_dialog.py` |

**Curve interaction (D-04, Photoshop convention — the `CurveWidget`):**

- **Click** on the grid adds a point at (input, output) and selects it; click within the **10px hit radius** of an existing point selects/drags it instead; click at an occupied x updates that point's y (last-wins at add-time — matches the LUT backstop).
- **Drag** moves the selected point; x is clamped strictly between its neighbors (endpoints at x=0/255 never move horizontally), y is clamped 0…255. **Endpoints are fixed at the corners (0,0)/(255,255) — draggable only along their edge** (y only) — D-04.
- **Double-click** a point deletes it; **endpoints can never be deleted** — D-04.
- **Keyboard (D-07 — StrongFocus on the widget):** arrow keys nudge the selected point **±1 unit, Shift = ±10**; **Tab / Shift+Tab** cycle point selection (endpoints included); the In/Out spinboxes track and drive the selected point.
- **In/Out spins:** `In` range = [prev_x+1, next_x−1] (x-order preserved), `Out` range 0…255; editing either moves the point (and the slider/gamma mirrors follow per the sync contract).
- Exactly **one point selected** at a time; the selected point is always the one the spins/arrows act on.
- **Preset row (D-05):** Linear (reset to the pure diagonal) / S-curve / Brighten / Darken — one click replaces the current channel's point set with the preset's starting points; **fully editable afterwards** (starting points, never locked): S-curve `[(0,0),(64,40),(192,215),(255,255)]`, Brighten `[(0,0),(128,150),(255,255)]`, Darken `[(0,0),(128,105),(255,255)]` (RESEARCH A2, locked here).
- **Channel switcher (D-06):** four exclusive checkable `QToolButton`s — **RGB / R / G / B** — accent checked state (ToolsPanel checked-tool rule). RGB edits the master; R/G/B edit independent per-channel curves. Switching preserves each channel's points.

**Sync contract (D-02/D-03 — the curve is the single source of truth; no state may diverge):**

- **Black point slider/spin ↔ left endpoint y** (input 0 → output value); **white point ↔ right endpoint y** (input 255 → output value). Dragging an endpoint on the grid updates the corresponding slider+spin; dragging the slider moves the endpoint along its edge. Cross-clamp (T-05-07, ONE mechanism, `_updating`-guarded): black max = white−1, white min = black+1 — mirrors `levels_dialog._refresh` verbatim.
- **Gamma ↔ midpoint anchor (D-03):** gamma is defined as the curve's **sampled output at input 128** (always well-defined — the piecewise-linear interpolation makes it independent of whether an explicit (128,y) point exists). Setting gamma g positions y = round(255 · 0.5^(1/g)) at input 128 (injecting/moving the point there); gamma 1.00 ⇒ mid = 128 (diagonal). Dragging the point at/near input 128 updates the gamma control in return via g = ln(0.5)/ln(y/255). Range 0.10…4.00, default 1.00, log-scaled slider (the inherited `_gamma_to_slider`/`_slider_to_gamma` mapping).

**Histogram (D-08):** computed **once** at dialog open from the detached `page_image` (`.copy()` discipline — Pitfall 2/5) via `np.histogram(..., bins=256, range=(0, 256))`: **luminance** `0.299R+0.587G+0.114B` for the RGB master, the per-channel plane for R/G/B (RESEARCH A7, locked). Rendered as normalized-linear bars (max bin = full grid height, clipped) at `rgba(232,232,234,0.14)` **behind** the gridlines. Never updates during editing (D-08 "computed once").

**Lifecycle (collector + preview driver — Pitfall 9; the b376f8a ordering MUST NOT regress):**

- `_on_curves` (renamed from `_on_levels`): `base = canvas.get_image_numpy().copy()` (Pitfall 2) → open dialog with `page_image=base` + `preview_callback` that runs `image_ops.curves_page(base, master, channels)` through the capture-suppressed `set_image_from_numpy_preview` path (never re-baselines Show Original mid-dialog).
