<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canvas mask/image -> history stack | live QImage/numpy state crosses into the history; lifetime hazard if not .copy()-detached |
| history stack -> canvas (undo apply) | popped snapshot crosses back to the canvas; must not hold a shared reference with the internal list |
| inpaint worker -> image stack | numpy patch from the worker crosses into the image undo stack |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11c | Tampering (QImage/numpy buffer lifetime — use-after-free via undo) | core/history_manager push/pop + canvas.apply_undo_mask/apply_undo_image | high | mitigate | EVERY push and pop enforces `.copy()`: push_mask_state stores `mask_qimage.copy()`; pop_mask_undo/pop_mask_redo stash `current.copy()` AND return `previous.copy()`; push_image_action stores `patch.copy()`; pop_image_undo/pop_image_redo slice with `.copy()` and return `.copy()`. The two regression guards test_mask_snapshot_is_copied and test_mask_pop_returns_copy prove the detachment. This is RESEARCH Pitfall 2 applied to the undo path (PATTERNS.md §Shared Pattern 5). |
| T-01-15 | Tampering (out-of-bounds image patch on undo) | canvas.apply_undo_image | medium | mitigate | apply_undo_image validates the patch fits within `[y:y+h, x:x+w]` of the current image before compositing; an out-of-bounds patch (e.g., from a stale history entry after a page crop — a Phase 5 concern) is clipped or no-ops defensively rather than corrupting the image array. (RESEARCH §Security Domain V5 input validation.) |
| T-01-16 | Denial of Service (unbounded history memory) | HistoryManager stacks | low | mitigate | Both stacks enforce a `limit` (default 20, MangaCleaner_GPU Config.MAX_HISTORY); the oldest entry is dropped on overflow. Full QImage snapshots at ~10000x10000px could be large, but the limit caps total memory at ~20 snapshots — acceptable for Phase 1 per RESEARCH Open Question 3 (optimize to incremental only if needed). |

Note: undo/redo is a low security surface overall — it operates entirely on in-process, user-generated state with no untrusted input crossing a trust boundary. The threats above are memory-safety (T-01-11c), bounds (T-01-15), and resource (T-01-16) rather than STRIDE spoofing/elevation. No path-traversal, model-tampering, or injection threats apply to this plan.
