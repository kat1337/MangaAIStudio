# Phase 7 — UI Design Contract (Typesetting: render translated text into the page)

> Visual and interaction contract for the Phase 7 typesetting layer (TRAN-02).
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **CRITICAL CONTEXT — PySide6 / Qt6 DESKTOP application, not a web app.** This
> contract is a **delta + reaffirmation** of `06-UI-SPEC.md` (approved 2026-08-09),
> which itself extends Phases 1/3/4/5. Every token NOT explicitly overridden
> below is inherited unchanged: the dark Fusion palette
> (`#232328`/`#2d2d33`/`#00d4ff`/`#e8e8ea`/`#9a9aa2`/`#3a3a42`/`#0b0b0e`), the
> 4/8/16/24/32/48/64 spacing scale, the typography table (Body 14px / Small
> 12px / Mono 12px / Heading 16px, Regular + Semibold), the canvas z-stack
> (text overlay z=120, badge z=140, handles z=150, inline editor z=1100), the
> Inspector panel pattern (QFormLayout + class-scope Signals + `connect_commit_handlers`),
> the BOXES undo stack + unified Ctrl+Z, the §16 text-overlay contract (zoom
> clamp, fit-in-box, current-focus rule), the §17 badge, and the §18 Inspector
> layout.
>
> **The phase's single biggest philosophical shift:** Phase 4's text overlay is
> a **translucent review aid** ("NOT an opaque caption" — 04-UI-SPEC §Color).
> Phase 7's D-01 makes the canvas text **final-quality opaque typeset output**
> whose look is per-box user-controlled — and a new export action (D-02)
> bakes exactly what the canvas shows. This supersedes the Phase 4 overlay
> *look* (translucency + hardcoded style) while inheriting its *machinery*
> (zoom/geometry tracking, fit-in-box, current-focus rule). It also makes the
> one deliberate, documented exception to Phase 1's "artwork is the sole
> saturated surface": **typeset glyph fills are reader-facing output and MAY be
> saturated** (user-chosen colors). Chrome, overlays, and the default style
> stay desaturated (§Color).
>
> All 16 locked decisions (D-01…D-16) come from `07-CONTEXT.md` (2026-08-10).
> Nothing in this contract is re-asked — pre-populated from the locked
> decisions + the inherited design system.

### The saturation exception (documented, deliberate — CONTEXT canonical_refs)

Phase 1 locked "the artwork is the sole saturated surface". Phase 4's text stayed desaturated-greyscale (a documented exception to the *bright*-surface corollary). Phase 7's D-01 makes canvas text **reader-facing typeset output** — CONTEXT explicitly notes "typeset text is reader-facing and CAN be saturated — this is the deliberate exception the typesetting phase makes". Locked here:

1. **User-chosen typeset glyph fills MAY be saturated** (any color in the `QColorDialog` palette — e.g. a red SFX, a yellow scream, a colored speech-bubble text). This is the feature, not drift.
2. **The exception is scoped to typeset glyph FILLS only** — inside the box's text content, on both the canvas and the bake. It does NOT extend to chrome (buttons, labels, borders, badges, overlays), which keep the inherited reserved-use rules; the accent `#00d4ff` remains reserved; box borders keep their origin hues.
3. **The DEFAULT style stays desaturated** (`#e8e8ea` fill, `#0b0b0e` outline, black shadow) — a fresh box renders exactly like the Phase 4 overlay minus translucency. Saturation is opt-in per box.
4. Effects (glow/shadow) are per-glyph color layers of the same text — they follow the same exception (the glyph is saturated → its glow/shadow may be).

**Accent `#00d4ff` is NOT used for typeset text, styling controls, swatches, or the Mixed state.** The reserved list (Phase 1 #1-6 + Phase 6 #7-10) is unchanged.

## Interaction & Surface Contracts (Phase 7 — the new + extended surfaces)

### Z-order on the scene — **UNCHANGED** (additive note)

Phase 7 adds **no new scene items**. The typeset renderer, effects, and tategaki layout render **inside the existing text-overlay child** (z=120) of each `BoxItem`; multi-select reuses the existing selection styling (3px border + hue tint) plus the primary box's existing handles (z=150). The z-stack from 05/06-UI-SPEC stands: image/mask 0 → boxes 100 → **text 120 (now opaque, styled, possibly vertical)** → badges 140 → handles 150 → empty-box hint 850 → crop dim 880 → preview 900 → cursor 1000 → inline editor 1100 → empty-state 2000.

### "Current focus" rule — UNCHANGED (D-04 inherits it verbatim)

The Phase 4 rule (translation when present, else recognized text; never both) governs BOTH the canvas rendering AND the bake content. Boxes with neither render/bake nothing. The Phase 4 view toggles (mask `M`, box `Shift+M`, text `T`) are **view-state only**: they never change box data, and the bake renders regardless of toggle state (D-04 default).

### 32. Multi-select surface · D-08/D-09/D-10 · (`gui/canvas.py` + `gui/box_item.py`)

Lifts Phase 3 D-08 single-select. The box layer stays tool-agnostic; no new tool, no marquee (declined).

- **Selection mechanics (D-08):**
  - **Click** a box (no Shift) → single-select it, deselecting all others (Phase 3 behavior unchanged).
  - **Shift+click** a box → **toggles** its membership in the current selection (adds if unselected, removes if selected; if removing the primary, the selection keeps its other members and a new primary is picked — planner's pick, e.g. the last-selected remaining).
  - **Click empty canvas** (no Alt) → clears the selection (deselects all), then falls through to the existing mask-tool dispatch (unchanged).
  - **`Ctrl+A` (Edit ▸ Select All Boxes)** → selects every box on the page. Enabled iff ≥1 box exists AND no async op is running.
  - **`Esc`** → deselects all.
- **Selection affordance (D-08/D-09, additive to Phase 3 §12c):**

  | State | Border | Fill | Handles |
  |-------|--------|------|---------|
  | Single selected (N=1) | 3px solid hue | `rgba(hue, 0.12)` | 4 corners on the box (Phase 3 unchanged) |
  | Multi selected (N>1) | 3px solid hue on ALL | `rgba(hue, 0.12)` on ALL | 4 corners on the **PRIMARY (last-clicked)** box only |
  | Unselected | 2px solid hue | transparent | hidden (unchanged) |

  Rationale: handles on every selected box is clutter (the Phase 3 single-select rationale); the primary-box handles signal "this is the group anchor — resize stays single-box" (D-09). The 3px + tint on all members keeps group membership readable at a glance. Origin hues (green/amber) apply per box as before — a mixed-origin group shows both hues' selected states.
- **Grouped move (D-09):** dragging ANY selected box's body moves the WHOLE group (the same delta applied to every selected box). No per-box commit: on release, ONE `box move` record pushes ONE BOXES snapshot (the full pre-move boxes list) — one Ctrl+Z reverses the whole group op. The status flash "Moved {n} boxes — press Ctrl+Z to undo." fires. Drag-arming on a member that is NOT the primary still drags the group (any member drags the group); the delta is applied to all selected.
- **Grouped delete (D-09):** `Delete`/`Backspace` with a multi-selection removes ALL selected boxes, silently (no confirm — Phase 3 D-12), ONE `box delete` BOXES snapshot (pre-delete full list), status flash "Deleted {n} boxes — press Ctrl+Z to restore." Single-box delete keeps the Phase 3 behavior + singular flash.
- **Resize stays single-box (D-09):** corner handles exist only on the primary box; dragging them resizes that box alone (the Phase 3 state machine untouched — no grouped resize).

No per-control commits mid-drag: combo/spin/swatch commits fire on the established commit signals (combo `currentIndexChanged`→but gated by the load-block, spin `editingFinished`, checkbox `toggled`, color dialog close).

### 34. Opaque typeset canvas rendering · D-01/D-11/D-12/D-14/D-15 · (`gui/box_item.py` + new `core/` typeset renderer)

**SUPERSEDES Phase 4 §16's look** (translucent `rgba(232,232,234,0.85)` fill + fixed 2px outline) with per-box user-controlled **opaque** rendering. The existing machinery — plain-text `QTextDocument`, `QTextCharFormat` merge (Pattern 3), `setTextWidth` wrap, `apply_overlay_zoom`, `_reposition_text_overlay`, `_current_focus_text`, T-toggle visibility — is retained and restyled.

- **Style-driven render (D-05/D-06/D-15):** the hardcoded `_OVERLAY_*` constants become the per-box `TextStyle` defaults (see §Color/§Typography defaults). Every refresh reads the box's style: font family + style, size (manual or Auto-fit), color, alignments, effects, vertical flag.
- **Opaque fill (D-01):** glyph fill renders at the style color, **fully opaque** (no alpha). Default `#e8e8ea`. Saturation allowed per §Color.
- **Manual size vs Auto-fit (D-15):**
  - **Auto-fit ON** (default): the inherited machinery verbatim — box-adaptive base `14 × min(box_w, box_h)/100`, [10,28] viewport-px clamp on the base, bounded shrink-to-fit (12 × 0.9, floor 5 vp), wrap at inner width. Behavior identical to Phase 4 for un-styled boxes.
  - **Manual size ON:** wrap at inner width; **no clamp, no shrink** — the text renders at exactly the set size and **overflows unclipped** beyond the box (single visual truth, §UI Considerations overflow row). The box border remains visible as the layout guide.
- **Effects (D-14):** outline via the existing `QTextCharFormat.setTextOutline` merge (Phase 4 Pattern 3 — width + color from style; width 0 = no outline); outer glow + drop shadow via the executor's choice of `QGraphicsDropShadowEffect` (0-offset dark shadow = glow; offset shadow = drop shadow) or `QPainter` passes — the contract is the LOOK (soft halo / offset soft shadow at the declared colors+widths), not the mechanism. Effects apply per-glyph in both horizontal and vertical rendering. **Performance guard (04-08 RC-1 lesson):** effect application must not regress the per-mousemove reposition path — effects render inside the single text item; a full rebuild per mousemove is prohibited (the planner designs the caching).
- **Tategaki / vertical rendering (D-11/D-12/D-13):** boxes with `payload.vertical=True` render through the **custom vertical layout path** — glyphs upright, lines top-to-bottom, columns advancing right-to-left from the box's top-right inner edge, column width 1 em, inter-column gap 0. NOT `QPainter.rotate` on the block (D-11 rejected). Mechanism (per-char/run paint vs custom `QAbstractTextDocumentLayout`) is researcher/planner discretion; the contract is the LOOK + the correctness bar (§UI Considerations backstop row): upright CJK, RTL column flow, **Latin letters + digits rotated 90° clockwise** (Japanese convention). Punctuation compression (kumimoji) is NOT implemented (future polish — CONTEXT §deferred). Alignment semantics in vertical mode: **Align** controls the column block's left/center/right position across columns; **Align V** controls its top/middle/bottom position along the column axis (same field values, vertical-layout interpretation; defaults Center/Middle). Auto-fit in vertical mode: fit loop operates on the column count (columns = floor(inner_w / 1em)) and the vertical extent of the run — the same bounded loop, applied to the vertical metrics; the [10,28] base clamp applies to the glyph size as in horizontal mode.
- **Inline editor stays horizontal (D-12):** the 04-05 `QGraphicsProxyWidget` editor is untouched — vertical is render+bake only. Editing flow: type horizontally, canvas displays vertically.
- **Zoom behavior:** scene-units (text scales with zoom — Phase 4 §16 rationale unchanged); Auto-fit mode keeps the [10,28] viewport-px clamp on the base; manual size renders unclamped at any zoom (the user's explicit size is the truth — WYSIWYG).
- **Visibility (unchanged):** the T toggle (surface 19) still hides the text children (review state); the box layer toggle `Shift+M` hides boxes incl. text; `M` mask overlay independent. Bake ignores all three (D-04).
- **Single renderer (D-01):** the style→render functions live in a shared, headless-testable `core/` module (planner discretion, alongside `image_ops.py`) consumed by BOTH the canvas overlay and the bake compositor — one visual truth, no drift. ASVS V5 discipline: styling must NOT introduce `setHtml`/rich-text injection — keep the plain-text document + `QTextCharFormat` merge (untrusted OCR/translation text).

### 35. Bake export · D-02/D-03/D-04 · (`gui/main_window.py` + the shared renderer)

- **Action:** File ▸ **Export Typeset…** (`Ctrl+Shift+B`), placed in the File ▸ Export section **after Export OCR JSON…** (sibling of Export Page… / Export OCR JSON…, not a replacement — D-02). Enabled iff a page is open AND no async op is running.
- **Dialog:** `QFileDialog.getSaveFileName`, filter **`PNG Image (*.png);;JPEG Image (*.jpg *.jpeg)`** (the Export Page filter), default filename **`{page-stem}_typeset.png`**, default directory per D-03 (below). User may override the location in the dialog (the D-22 override precedent).
- **Content (D-02/D-04):** the page's **current image state** (cleaned/edited — the same image the canvas shows, same coordinate space as `_ocr.json`) with the typeset text composited per box using **the shared renderer** (§34). Per-box content follows the current-focus rule (translation when present, else recognized; neither → nothing). The composite renders onto a **detached copy** (Pitfall 2 — never the live canvas image) and writes via `core/image_io.save_image_optimized` (PNG compress 9 / JPG quality 95, DPI preserved — the PROJ-02 contract).
- **Location rule (D-03 — the D-22 mirror):** pristine page (no geometry op since load) → the **source page's folder** (sidecar next to the source, `{stem}_typeset.png`); geometry-altered page → the **`cleaned/` sibling folder** (created if missing). Default dir per this rule; overridable in the dialog.
- **Overwrite:** the sidecar is a generated artifact — overwrite silently (Export Page precedent), no confirm.
- **Feedback:** inline synchronous execution (fast, no model — §UI Considerations loading row). Completion: transient **"Typeset exported → {filename}"**. Failure: **"Couldn't save '{filename}'."** `QMessageBox::Critical` (Phase 5 copy). No progress bar, no Worker required (planner may add the Worker if profiling shows a need — the Phase 2 gate; the UI surface is contracted for the inline path).
- **WYSIWYG guarantee (D-01/D-04):** the bake renders EXACTLY what the canvas shows — same renderer, same styles, same current-focus content, same manual-size overflow (clipped only at the page edge), same vertical layout. View toggles (M/Shift+M/T) do NOT suppress baking (default).

- `Ctrl+A` — verified free: no existing binding in the Phase 1–6 shortcut map (Ctrl+O/S/Q/E/Z/R/0/1/+/-/Shift-variants taken; A unbound). Convention: "select all" is the universal meaning. No collision.

## Accessibility & Platform Notes (Phase 7 delta)

- **Contrast — chrome:** inherited token math unchanged (`#e8e8ea` on `#2d2d33` ≈ 10:1; muted `#9a9aa2` ≈ 4.6:1 for labels). The Style section uses only inherited tokens; the 12px semibold muted section header meets the muted-label rule (non-essential labeling).

The DEFAULT style preserves the Phase 4 legibility guarantee: light `#e8e8ea` fill + 2px dark `#0b0b0e` outline reads on any artwork background (the outline+fill combination is the standard scanlation treatment). Auto-fit's 5-vp floor + the outline guarantee remain the readability backstop. The "Mixed" swatch keeps ≥4.6:1 on both halves.
- **Keyboard:** every Phase 7 action is keyboard-reachable — Select All Boxes (`Ctrl+A`), font size +/− (`Ctrl+]`/`Ctrl+[`), Export Typeset… (`Ctrl+Shift+B`), all styling controls are standard `QFormLayout` fields (focus-navigable; `QFontComboBox` is typeable, `QSpinBox`es are editable, `QColorDialog` is fully keyboard-driven). - **High-DPI:** no new viewport-px elements (typeset text is scene-px by design — it is part of the artwork's coordinate space). Effects render in scene space and scale with zoom. Re-test at 150%/200% per the Phase 1 mandate (backstop rows §UI Considerations).
- **Font fallback / CJK:** the default font (Liberation Sans) has no CJK glyphs — Japanese text renders via Qt's system font fallback, exactly as the Phase 4 overlay does today. The executor must NOT disable fallback. When the user picks a font, `QFontComboBox` lists system fonts only (no bundling — CONTEXT §deferred: font management is out of v1).
- **IME:** unaffected — the inline editor + Inspector text fields keep their Phase 4 IME support; styling controls are non-text widgets.
- **Platform:** Windows-first (inherited). Fusion style + QPalette keep rendering identical on Linux later.
