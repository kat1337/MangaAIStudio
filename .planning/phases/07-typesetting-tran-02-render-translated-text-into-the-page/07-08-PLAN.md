Close **G-07-5 (major)** from 07-UAT.md: "align V doesn't work with horizontal text". Root cause (already diagnosed): the renderer computes the align_v dy correctly (text_renderer.py:560-565, applied to the origin at :580-583), but `TypesetOverlayItem.set_content` (box_item.py:388-395) cancels `result.origin` IN FULL and re-derives the position from the document-local ink rect — `_ink_offset = QPointF(ink.left() - pad, ink.top() - pad)` drops the dy on canvas (the bake keeps it → canvas ≠ bake for align_v != top). The vertical path yields dy=0 → unchanged.

Purpose: preserve the box-relative origin delta in the overlay's ink-offset geometry (`_ink_offset.y += dy` where `dy = origin.y - box.y - inset`) and close the test blind spot — the existing equivalence tests all use align_v top.

Output: the dy-preserving ink-offset formula and overlay-level canvas≡bake tests with align_v middle/bottom.
</objective>
