### The border-state contract (D-11/D-12 — THE token mapping decision)

Phase 3 encoded **origin** in the border hue. Phase 8 adds a second dimension
without disturbing the first: **stroke style encodes outcome, hue encodes who
decided.** The user's mental model (CONTEXT §specifics, D-12): the border is a
live answer to *"what would happen if I pressed C right now?"* — not a history
report.

| Inpaint state | Derivation (pure function of PageBox fields + threshold — RESEARCH §8) | Border, unselected | Selection tint |
|---|---|---|---|
| **will-inpaint** | Auto, gate passes: `std_dev ≤ threshold` AND box has auto mask content | **Origin hue, 2px SOLID** — the Phase 3 look, unchanged | `rgba(hue, 0.12)` |
| **gate-skipped** | Auto, gate fails (`std_dev > threshold`) OR no auto content (noise box / no detected text inside) | **Origin hue, 2px DASHED** (6/4 scene px) | `rgba(hue, 0.12)` |
| **forced** | Override = Always | **`#e8e8ea`, 2px SOLID** | `rgba(232,232,234,0.12)` |
| **never** | Override = Never | **`#9a9aa2`, 2px DASHED** | `rgba(154,154,162,0.12)` |
| *(mode-off)* | Detect Boxes OFF (D-03) — no boxes exist | n/a (no box layer) | n/a |

**Reading rules (executor-authoritative):**

1. **Solid = "C will inpaint this box's detected text." Dashed = "C won't."** This is the one-glance answer D-12 requires; it is encoded in *pattern*, not hue, so it survives color-blindness and low-luminance artwork.
2. **Hue = who decided.** Green/amber (origin hues) = the automatic std-dev gate decided. Greys = the user's override decided (`#e8e8ea` = forced-in, `#9a9aa2` = forced-out). An override state *replaces* the hue until flipped back to Auto (origin is still visible in the Inspector Origin field and drives D-03 re-detect behavior regardless of rendering).
3. **Selection stays width-encoded** (2px → 3px + tint + handles) — the Phase 3/7 selection affordance is untouched; the selected border uses the current state hue/style at 3px. Handles, bubble badge (z=140), text overlay (z=120), and Phase 7 typesetting render unchanged — states modify only the box rect's `QPen` (the `set_inpaint_state(state)` extension of `_apply_origin_pen`/`_apply_look_for`, box_item.py:549/:626).
4. **The border speaks for the detected/auto path only.** Hand-painted mask content inside any box is ALWAYS inpainted (D-01) and is already visible as red mask overlay — the border never claims otherwise. Gate-failed/Never boxes contribute nothing to the mask layer (RESEARCH Q8's reading, stated here as the UI truth: dashed borders and an empty-looking mask region are consistent — "skipped" means *no mask*, not *masked but ignored*).
5. **No state on user boxes pre-detection:** a box with no fit data (std_dev `None`, no auto content) renders **dashed** — honest ("as things stand, C will not clean this box") and transient (boxes are fitted at detect/create-commit per RESEARCH Q4's recommendation). Post-`.mas`-load, states restore from the round-tripped per-box `mask`/`std_dev`/`override` fields (criterion 5), so restored pages render correct borders without a re-detect.

**Live updates (D-12, predictive):** borders re-derive (cheap — pure field comparison + one item repaint) on: detection finish, **std-dev threshold change**, **dilation radius change** (re-dilate → auto content changes → gate re-derives), override flip, box move/resize **release** (recompute the moved box's std-dev once, then re-derive — never per-mousemove; RESEARCH §8 debouncing), re-detect, page load/restore. Implementation shape: a `refresh_box_inpaint_states()` helper iterating `canvas._box_items`, calling `PageBox.inpaint_state(threshold)` (model-layer, headless-testable) → `BoxItem.set_inpaint_state(state)`.

### 37. Per-box inpaint border states · MASK-02/03, D-11/D-12/D-09 · (`gui/box_item.py` + model)

The full token mapping lives in §Color (the border-state contract table) —
that table IS the contract. Implementation surface:

- **`BoxItem.set_inpaint_state(state)`** — the fourth pen dimension alongside origin/selection (extends `_apply_origin_pen` box_item.py:549 and `_apply_look_for` :626; the state computes hue-or-grey + solid-or-dashed, then the existing selection width/tint logic applies on top). One item repaint per change — negligible cost.
- **State derivation** is a **pure model function** — `PageBox.inpaint_state(threshold)` per RESEARCH §8: `forced` when override == "always"; `never` when override == "never"; `will-inpaint` when Auto AND std_dev ≤ threshold AND the box has auto mask content; else `gate-skipped`. Headless-testable; no UI logic in the derivation.
- **Refresh triggers** (one `refresh_box_inpaint_states()` MainWindow helper over `canvas._box_items`): detection finish, threshold change, radius change, override commit, box move/resize **release**, re-detect, page load/`.mas` restore. Never inside `mouseMoveEvent` (Pitfall 14 discipline; std-dev recompute happens once, on release).
- **Coexistence (all unchanged, verified by z-order):** selection = 3px + tint + handles (state hue at selected width); Phase 4 bubble badge sits TL-outside (never touches the border); Phase 7 typeset text renders inside the box (z=120 above the border); the red mask overlay (z=0 layer) shows underneath. A dashed border over the red overlay must stay readable — the UAT backstop row.
- **Mode-off (D-03):** no boxes → nothing to show; mask-only pages keep the Phase 1 look exactly. Pages in mask+boxes mode with **zero boxes detected** show an empty mask layer (D-02 discards everything) — deliberate per D-01/D-02; surfaced as UAT copy, not a new UI element.

### 39. Paint-under-boxes dispatch · MASK-06, D-15/D-16/D-17/D-18 · (`gui/canvas.py` mousePressEvent)

**Interaction-only — zero visual change (D-18).** Boxes render identically
under every tool; only the press-dispatch routing changes (the carve-out to
Phase 3 D-07 "boxes always interactive"). `PAINT_TOOLS = {BRUSH, RECTANGLE,
LASSO, ERASER}` (Crop excluded — D-17).

| Press on… | Move/Pan (V) / no tool context | Crop (G) | Paint tool (B/R/L/E) |
|---|---|---|---|
| Box body | select + move (today) | select + move (today) | **PAINT — passes through (MASK-06)** |
| Corner handle | resize (when sole selection — today) | resize (today) | **PAINT — passes through (bodies AND handles, D-15)** |
| **Alt**+click box body | select (today's box branch) | select | **select** (D-15) |
| **Alt**+drag box body | select + move | select + move | **select + move** (D-15; the Phase 7 group-move machinery if multi-selected) |
| **Alt**+drag empty canvas | create box (today) | create box | **create box** (unchanged — D-15 keeps create on EMPTY canvas only) |
| **Shift**+click box | toggle selection membership (Phase 7 D-08) | toggle | **PAINTS** — the Shift-toggle is unreachable while painting (documented in the paint tooltips' Alt clause; the Shift Brush↔Eraser toggle is a keyPressEvent, not a mouse modifier — no conflict) |
| Double-click box | inline editor | inline editor | **inline editor (D-16 — always, any tool)** |
| Drag empty canvas | pan | crop rect | paint stroke (today) |

- **Dispatch order (the contract):** inline-editor guard → pan → **box branch (now Alt-gated under paint tools)** → crop branch → paint branch → super(). Under a paint tool WITHOUT Alt, the box branch falls through entirely — the paint branch receives presses that land on box bodies and handles exactly as if the boxes weren't there. Under Move/Pan and Crop, today's box branch runs verbatim (Alt behaves as today: not special on a box hit).
- **Alt+handle under paint tools:** resize engages only when the handle's box is the sole selection (today's gate, :1063-1066); otherwise a dead press — identical to today, kept.
- **Eraser pass-through:** eraser strokes land under boxes identically to empty canvas (what they subtract from the composite is the layered-model's business — RESEARCH Option B; the UI truth is "no dead spots under boxes").
- **Education:** the four paint tool tooltips carry the Alt clause (Copywriting); no new chrome, no mode indicator (D-18).

## Accessibility & Platform Notes (Phase 8 delta)

- **Color-blind safety — the load-bearing property of §Color:** the yes/no outcome is encoded in **stroke pattern** (solid vs dashed), never hue alone; the override states (`#e8e8ea` vs `#9a9aa2`) additionally differ in luminance (near-white vs mid-grey ≈ 2.4:1 apart), inheriting the Phase 3 rationale that origin hues also differ in luminance. All four states are distinguishable under deuteranopia/protanopia.
- **Contrast:** `#e8e8ea` forced border on artwork/matte is the highest-contrast border in the app; `#9a9aa2` dashed is the weakest by design (demoted state) but ≥3:1 on the matte and pattern-redundant (WCAG 1.4.11 non-text). Inspector/dock chrome uses inherited tokens (≈10:1 / 4.6:1 — inherited rules).
- **Keyboard:** every new control is keyboard-operable (§Shortcut Reference). The one new mouse gesture (Alt+click select under paint tools) has no keyboard twin *under paint tools*, but box selection itself remains reachable by switching to Move/Pan (`V`) and using the mouse as today — no regression versus Phase 7 (per-box keyboard selection remains a v2 candidate, unchanged).
- **Focus:** the accent 2px focus outline (reserved use #3) applies to all new widgets — checkboxes, sliders, spins, the combo, the scroll area's children.
- **High-DPI:** no new viewport-px elements (the dash pattern is scene-units and scales with zoom, like the border itself). Re-test at 150%/200% per the Phase 1 mandate — the border-state backstop covers it.
- **Screen-reader/IME:** no impact — labels are standard `QFormLayout` buddies; no text input is added.
- **Platform:** Windows-first (inherited). Alt as a mouse modifier is well-behaved on Windows Qt (proven since Phase 3's Alt+drag create).

## Open Questions for the planner (surfaced by the UI researcher — not blocking this spec)

1. **First-press dot before the double-click editor (RESEARCH §7.2/Pitfall 13):** under a paint tool, the first press of a double-click paints one undoable dot on the box before the inline editor opens. This spec accepts it (one dot, Ctrl+Z); the planner may suppress it — either is consistent with the contract.
2. **Raw heatmap `.mas` persistence (RESEARCH Q6):** UI states restore from the per-box fields regardless (§37 rule 5); if the raw mask is NOT persisted, post-load radius changes silently no-op on never-re-detected pages (D-08's no-op case) — planner decides persistence, and whether a transient "no detection data" flash is wanted (not contracted).
3. **Erase-of-auto-content border interplay (RESEARCH §2.4):** locked default here — the border reflects gate + override ONLY; the erase is visible on the mask itself. Planner confirms against the layered-model implementation.
4. **Std-dev display rounding:** `{value:.1f}` locked; if gate comparisons display inconsistently (e.g. 15.0 shown passing at threshold 15), the planner may align the shown precision with the threshold spin's 1-decimal step — cosmetic.
5. **"Detection complete" flash extension** (not contracted): the detect-completion flash could also report box/gate counts; left to the planner as optional polish — the contracted predictive surface is the border itself.
