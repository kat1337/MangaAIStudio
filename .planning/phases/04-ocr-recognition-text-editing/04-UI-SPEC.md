# Phase 4 — UI Design Contract (OCR Recognition & Text Editing)

> Visual and interaction contract for the Phase 4 text layer. Generated by
> gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **CRITICAL CONTEXT — PySide6 / Qt6 DESKTOP application, not a web app.** This
> contract extends the Phase 1 + Phase 3 design systems (see
> `01-cleaning-workspace/01-UI-SPEC.md` and
> `03-text-box-detection-interaction/03-UI-SPEC.md`). It speaks Qt, not CSS:

> `QDialog`, `QSpinBox`, `QComboBox`, `QFormLayout`, `QMessageBox`, `QShortcut`.
> Design tokens here are the source of truth for the executor.
>
> **Relationship to Phase 1 + 3:** this is a *delta + reaffirmation*. Every

> + Phase 3 contracts (color palette, spacing scale, typography, Fusion style,
> dark QPalette, canvas matte `#0b0b0e`, mask overlay `rgba(255,0,0,0.63)`,

> correction objects, not display objects" because Phase 3 had no text. Phase 4

### Reconciling the text overlay with "artwork is the sole saturated surface"

This is the key design tension the UI researcher owns (per the orchestrator brief). Resolution:

1. **The text overlay is DESATURATED, not saturated.** Fill is `#e8e8ea` (near-white grey, no hue), outline is `#0b0b0e` (the matte black, no hue), badge fill is `rgba(0,0,0,0.72)` (pure black, no hue). Phase 1's principle targets *hue saturation* (the mask red, the accent cyan, the box green/amber are the only saturated surfaces, and they are all semantic chrome, not artwork). Greyscale text is hue-neutral → it does not violate the principle. The artwork remains the sole *colored* surface.
2. **The text overlay is TRANSLUCENT** (0.85 alpha fill) so artwork reads through — explicitly required by D-11. It is a review/correction aid, not a replacement of the art (D-11 anti-goal: "NOT an opaque caption").
3. **The bubble-number badge is the one near-opaque element** (`rgba(0,0,0,0.72)`) because a number must be unambiguously readable against arbitrary artwork. It is tiny (20×14 viewport px) and desaturated → it reads as a small label chip, not a competing surface. (Same reasoning Photoshop/Krita use for layer-number badges.) 04-10: the badge is now digit-sized (§17 amendment) — still the one near-opaque element, sized to its glyph rather than a fixed asset.
4. **This is a deliberate, documented exception** to "artwork is the sole bright surface" (Phase 1's corollary) — D-09 upgrades boxes to display objects, which requires text on the canvas. The exception is scoped to the *desaturated greyscale text + badge*; it does NOT open the door to saturated canvas chrome. Recorded here so the checker/auditor sees the rationale, not a silent drift.

**Accent `#00d4ff` is NOT used for the text overlay, badges, or inline editor.** This preserves the Phase 1 reserved-for list (active tool, selected page row, focus outline, progress fill, running-op spinner, eraser-mode label) so the cyan stays meaningful.

### Z-order on the scene (concrete, executor-authoritative — Phase 4 update)

```

z=0     mask_item         (QGraphicsPixmapItem, above image — added after it)
z=100   box layer         (QGraphicsItemGroup / parent-less box items)
z=120   text overlay      (NEW — QGraphicsTextItem per box, child of the box;
                          renders the "current focus" text, translucent)

                          tools, AMBER dashed during box-create)
z=1000  cursor_item       (QGraphicsEllipseItem — existing brush outline)

                          ABOVE everything so it receives focus + is fully
                          visible while editing; only one exists at a time)
```

**The three things drawn on/near each box — text overlay (z=120), bubble-number badge (z=140), box border + handles (z=100/150) — must not visually collide.** The badge sits at the **top-left corner outside the box rect** (offset so it does not overlap the TL handle's hit area; see §17). The text overlay sits **inside the box rect, inset by the box border + a 2px margin** (see §16). The handles sit **on the corners**. The badge is the only element that extends outside the box rect; it is positioned at the TL corner's *outside* diagonal so it never covers a handle.

Boxes + text + badges sit **above the mask overlay, below the tool preview/cursor and the inline editor** (extends Phase 3's z-order). The inline editor (z=1100) is above the cursor (z=1000) so the text cursor inside the editor is the visible cursor while editing.

### "Current focus" rule (D-08 + D-10 — the single mental model)

> This rule governs BOTH the inline editor AND the canvas text overlay. It is
> the user's explicit mental model (CONTEXT §specifics): the reader-facing
> text is primary; the source text is secondary once a translation exists.

| Box state | Inline editor shows/edits | Canvas text overlay shows | Inspector shows |
|-----------|---------------------------|---------------------------|-----------------|
| No translation | Recognized text | Recognized text | Recognized (editable) + Translation (empty, editable) |
| Translation exists | Translation | Translation | Translation (editable) + Recognized (editable) |

A box **never shows both texts simultaneously on the canvas** (D-10). Both fields are **always editable** via one surface or the other: the inline editor edits the focus field; the Inspector edits both (the non-focus field is the Inspector's primary job, per D-08).

### 14. OCR actions surface · TEXT-02 · (`gui/main_window.py` + new `TorchOCRModel`)

- **Two OCR entry points (D-01):**
  1. **Auto-OCR on Alt+drag draw-release** — the Phase 3 `_begin_create_box` / `_commit_create` flow (`canvas.py:1402`/`:985`) is preserved; Phase 4 appends the OCR call after the empty-user-box commit. The gesture is unchanged from the user's perspective (Alt+drag still draws a box); the box now arrives with recognized text. If the box is < 8×8 scene px (Phase 3 no-op threshold), no OCR runs.
  2. **"Run OCR" action (selected box)** — Text → Run OCR. Runs manga-ocr on the single selected box. Enabled iff exactly one box is selected (Phase 3 is single-select, D-08) AND no async op is running.
- **"OCR All Boxes on Page" action (D-03)** — Text → OCR All Boxes (`Ctrl+R`). Fills every box on the current page that has no recognized text yet. ### 15. Inline text editor overlay · TEXT-04, D-05/D-06/D-07 · (`gui/canvas.py` + `gui/box_item.py`)

- **Trigger:** double-click a box (box layer visible). Phase 3's D-07 single-click=select/double-click=edit rule (CONTEXT D-07) is preserved — single-click still selects/moves/resizes; double-click enters edit mode. Edit mode disables move/resize while active (D-07). NO new tool added to the mask `QActionGroup` (D-07 honored).
- **Widget choice (CONTEXT Claude's Discretion — resolved here):** a **`QGraphicsProxyWidget` wrapping a `QTextEdit`**, parented to the canvas scene (NOT to the box item — parenting to the box would inherit the box's transform and break the editor's coordinate system). The proxy is positioned/sized to the box's viewport rect at edit-entry, inset 2px from the box border (so the border stays visible around the editor). z=1100 (above cursor). Rationale:
  - `QTextEdit` (not `QLineEdit`) — OCR text is multi-line (manga bubbles are multi-line); `QLineEdit` is single-line and would clip. `QTextEdit` supports both horizontal default + the vertical toggle (D-06) via `QTextOption`/`QTextDocument` writing-mode (see below).
  - `QGraphicsProxyWidget` (not a `QGraphicsTextItem` in edit mode) — `QGraphicsTextItem`'s built-in `setTextInteractionFlags` edit mode is fragile for multi-line + vertical text and gives no control over the editor's frame/background. A proxy widget gives a real `QTextEdit` with full text-edit affordances (cursor, selection, IME for Japanese input) + our own frame/background styling.
  - One editor instance at a time (a single `QGraphicsProxyWidget` reused, repositioned per edit session) — never two editors on screen.
- **Editor chrome:** background `#2d2d33` (Secondary), text `#e8e8ea` (Text primary), font 14px / 1.5 line-height Liberation Sans (Body role). 3px `#0b0b0e` frame (the matte — separates from artwork). The editor's outer rect is inset 2px from the box border so the box's origin-colored border (green/amber) + selection tint stay visible — the user sees *which box* they are editing.
- **Vertical-mode toggle (D-06):** the editor defaults horizontal. A per-box toggle (surfaced in the Inspector, §18) flips the editor to vertical (top-to-bottom, right-to-left columns). Implementation: `QTextOption.setTextDirection(Qt.Vertical)` + `QTextOption.setAlignment(Qt.AlignRight)` on the `QTextEdit`'s document. The `TextBlock.vertical` flag (from CTD detection) is **always preserved on the model regardless of editor mode** (D-06 — orientation is export metadata; the toggle is edit-UX). The toggle's checked state initializes from `payload.vertical` on edit-entry.
- **Commit / cancel (D-05):**
  - **Enter** (with no modifier, or `Ctrl+Enter` for multi-line insert — executor picks the least-surprising: `Enter` commits, `Shift+Enter` inserts a newline, the standard `QTextEdit` convention) → commit. The focus field (recognized if no translation, else translation — D-08) is written via the model setter; the `edited` flag is set true (D-04); a `text edit` or `translation edit` entry pushes onto the BOXES stack; the overlay (z=120) re-renders the new text; the editor proxy hides.
  - **Click-away** (click anywhere outside the editor proxy) → commit (same as Enter). The canvas's mouse-press dispatch checks "is the inline editor active? and is the click outside it?" before any other dispatch; if so, commit and consume the event.
  - **Esc** → cancel (discard edits since edit-entry; hide the proxy; no BOXES push). `Esc` is already used for batch-cancel + box-deselect (Phase 3 §12c); the canvas dispatch prioritizes "inline editor active?" first, so `Esc` while editing cancels the edit (does not deselect the box — the box stays selected so the user can immediately re-edit or move it).
- **Edit mode disables move/resize (D-07):** while the inline editor is active, the canvas's box hit-test dispatch returns early (no move/resize, no new selection). The corner handles remain visible (the box is still selected) but are not interactive until the editor commits/cancels.
- **WYSIWYG:** the editor's font size (16 scene px — see §Spacing exceptions) matches the rendered overlay's size at 100% zoom so editing shows the user what the overlay will look like. At other zoom levels the editor scales with the viewport (it is a proxy widget on the scene).

### 16. Persistent text overlay on canvas · TEXT-04 + TEXT-05, D-09/D-10/D-11 · (`gui/box_item.py`)

- **This is the "boxes become display objects" upgrade (CONTEXT §specifics).** Phase 3's `BoxItem` carried no text rendering; Phase 4 adds a child `QGraphicsTextItem` per box.
- **Widget:** a `QGraphicsTextItem` (or a `BoxItem.paint()` override drawing outlined text — executor picks; `QGraphicsTextItem` is simpler and supports `QTextDocument` for rich formatting if needed later). Child of the `BoxItem`, z=120 (above the box border z=100, below the bubble badge z=140 and handles z=150).
- **Geometry:** positioned inside the box rect, inset by the box border width (2-3px) + a 2px margin (so the text never touches the border). Width-clamped to the box's inner width; height grows as needed (text overflow is clipped at the box rect — the box is the text's container). Fit-in-box amendment (04-09 gap closure): the width clamp is implemented via `QGraphicsTextItem.setTextWidth` (inner width = box width - 2x inset, inset = border half-width + 2px); the base font is BOX-ADAPTIVE (14 x min(box_w, box_h)/100 viewport px, i.e. 14 for a 100 scene-px box) clamped to [10, 28] viewport px — the clamp bounds the BASE; a bounded shrink-to-fit loop (max 12 steps of 0.9, hard floor 5 viewport px, floor checked at loop top so no render lands below it) reduces the RENDERED font below the clamp when the wrapped text still exceeds the inner height, so the text 'tries to fit'; clipping remains only the pathological fallback.
- **Content (D-10 "current focus" rule):** renders **translation when present, else recognized text.** A box never shows both. Empty boxes (no recognized text yet) render nothing (the box border + badge are the only signals).
- **Color + outline (D-11, §Color):** fill `rgba(232, 232, 234, 0.85)` (translucent Text primary), outline `rgba(11, 11, 14, 0.92)` 2px behind glyphs. Implemented via `QGraphicsTextItem.setDefaultTextColor(...)` + a `QPainter` outline pass (draw the text 4-8 times offset by ±1px in the outline color, then the fill color on top — the standard outlined-text technique), OR a `QGraphicsEffect` (`QGraphicsDropShadowEffect` with a dark shadow at 0 offset, high blur radius — cheaper, slightly softer). Executor picks; the contract is the *look* (translucent white text + dark legibility halo, art visible underneath), not the mechanism.
- **Font + scaling (CONTEXT Claude's Discretion — resolved here):**
  - **Scene-units, not viewport-px.** The text scales with zoom (zoom in → text grows with the artwork; zoom out → text shrinks). Rationale: the text is *part of the box*, which is part of the artwork's coordinate space; viewport-px text would float at constant size while the box grows/shrinks, breaking the WYSIWYG edit experience (§15).
  - **Base size 14 scene px** at 100% zoom (Liberation Sans, the Phase 1 canvas-overlay font — `image_viewer.py:306`). Scales linearly with zoom. 04-09 amendment: the 14px base is scaled by the box's smaller dimension (min(box_w, box_h)/100), so larger boxes render larger text up to the [10,28] viewport-px clamp — the UAT test-1 fit-in-box truth (a 100 scene-px box keeps the original 14px base).
  - **Clamp the rendered viewport-px size to [10px, 28px]** (executor: compute `effective_px = base_px * zoom`; if `< 10` render at 10 viewport px via `ItemIgnoresTransformations` fallback, if `> 28` render at 28 viewport px). Below 10px the text is unreadable; above 28px it overwhelms the artwork. The clamp keeps the overlay useful across the full zoom range (Phase 1 clamps zoom to 0.5× viewport .. 100×). Implemented by scaling the scene font (clamp(14*zoom, 10, 28)/zoom scene px) rather than the ItemIgnoresTransformations fallback — same rendered [10,28] viewport-px contract, keeps the overlay a normal zoom-scaling child (04-08).
  - **Outline width 2px** (constant scene-px — does not scale with zoom; the halo is a fixed legibility aid, not a zoom-dependent feature).
- **Visibility (D-12):** the text overlay has its OWN visibility toggle (`T`, §19), independent of mask (`M`) and box (`Shift+M`). When the text overlay is off, the `QGraphicsTextItem` children are hidden (the box borders + badges can still show). When the box overlay (`Shift+M`) is off, the entire box layer (including text + badges) is hidden — text is a child of the box, so hiding the box hides everything. Three independent layers: mask / box-border+handles / text-overlay (the text toggle only affects the text children, not the borders).

### 17. Bubble-number badges on canvas · D-15/D-16 · (`gui/box_item.py`)

- **Widget:** a `QGraphicsRectItem` (the badge background) + a `QGraphicsTextItem` (the digit) as a child of each `BoxItem`, z=140 (above the text overlay z=120 + box border z=100, below the handles z=150). `ItemIgnoresTransformations` enabled → constant 20×14 viewport px at any zoom (same reasoning as Phase 3's 8×8 handle). 04-10 amendment (gap closure round 3): the badge is sized to its number — refresh_badge measures the digit's bounding rect (document margin 0 = the glyph line box) after setPlainText and resizes the badge rect to digit_w + 8 (4 px/side) by digit_h + 4 (2 px/side), re-centering the digit; the TL-outside placement and the edge-flip use the ACTUAL badge size, so the badge always hugs its number.
- **Position:** the badge sits at the **top-left corner, OUTSIDE the box rect** — offset by `(-badge_w - 2, -badge_h - 2)` from the TL corner so it sits in the diagonal outside-northwest quadrant. Rationale: (a) it never overlaps the TL corner handle's hit area (the handle sits *on* the corner; the badge sits *beyond* it); (b) the TL corner is the conventional "label" position (Photoshop layer badges, mokuro box numbers); (c) outside the box means it never covers the text overlay (which is inside the box). For boxes at the top-left edge of the page (badge would clip off-canvas), the badge flips to inside-top-left (inset 2px) — executor handles the edge case.
- **Content:** the bubble number (1..N), or empty/hidden if the box has no number assigned yet (auto-number not run, no manual override).
- **Styling (§Color):** badge fill `rgba(0, 0, 0, 0.72)`, digit `#e8e8ea` 12px Semibold (the one weight exception, §Typography), outline 2px `#0b0b0e` (matte). Manual-override badge (D-16) gets a 2px `#f5a623` amber border (the user-origin hue) so the user sees which numbers they touched. Auto-numbered badges have the matte outline only.
- **Reading order (D-15/D-16):**
  - **Default: RTL/TB (manga)** — page-level "Auto-Number RTL (Manga)" assigns 1..N right-to-left, top-to-bottom (column-bucketing then per-column top-to-bottom — the researcher/planner picks the exact thresholds per CONTEXT Claude's Discretion).
  - **Alternative: LTR/TB (manhwa)** — page-level "Auto-Number LTR (Manhwa)" assigns 1..N left-to-right, top-to-bottom.
  - **Per-box manual override (D-16):** the user can assign any number to a box via the Inspector (§18). Manual overrides stick when a page-level re-auto runs — conflict policy (CONTEXT Claude's Discretion): **manual overrides are preserved; auto re-numbers only the non-overridden boxes, leaving gaps in the sequence where a manual number collides.** (Least-surprising: the user's manual edits are never silently overwritten; gaps are visible and the user can resolve them.) A box whose auto-number was skipped (collision) shows its number with the amber override border so the user sees it was touched.
- **D-18 (page-global numbers):** the badge shows the page-global bubble number (1..N across the whole page, regardless of panel). Panel-aware numbering is deferred (CONTEXT §deferred).

## Accessibility & Platform Notes (Phase 4 delta)

- **Contrast:**
  - Text overlay fill `rgba(232,232,234,0.85)` on arbitrary artwork — the 2px dark outline (`rgba(11,11,14,0.92)`) guarantees legibility on any background (the outline + fill combination is the standard manga-scanlation text treatment; it is readable on pure white, pure black, and any hue). This is a *review overlay* (D-11), not strict-WCAG-body-text — the contract is "legible against arbitrary artwork", which the outline guarantees.
  - Bubble-number badge digit `#e8e8ea` on `rgba(0,0,0,0.72)` fill — luminance contrast ≈ 11:1, far above WCAG AA 4.5:1. The badge is small (12px) but high-contrast.
  - Inspector fields: Text primary `#e8e8ea` on Secondary `#2d2d33` — ≈ 10:1 (inherited, verified Phase 1). Muted labels `#9a9aa2` on `#2d2d33` ≈ 4.6:1 — use only for non-essential labels (inherited rule).
  - Inline editor: Text primary `#e8e8ea` on Secondary `#2d2d33` — same as Inspector.
- **Keyboard:** all Phase 4 actions are keyboard-reachable — Run OCR (Text menu, accelerable), OCR All (`Ctrl+R`), Toggle Text Overlay (`T`), Auto-Number (Text menu), Load Translations (Text menu), inline edit (`F2` or double-click), commit (`Enter`), cancel (`Esc`). The one mouse gesture — double-click to edit — has the `F2` keyboard equivalent (contracted). The bubble-number manual override is editable via the Inspector's `QSpinBox` (keyboard-accessible).
- **Focus:** the accent `#00d4ff` 2px focus outline (Phase 1 reserved use #3) applies to all new widgets — Inspector fields, Load Translations dialog controls, the Run OCR / OCR All actions. Box selection on canvas continues to use the origin-colored border + handles, NOT the accent. The inline editor's focus is the text cursor inside the `QTextEdit` (Qt's native text-edit cursor).
- **High-DPI:** bubble badges + the inline editor's 3px frame use viewport-px / `ItemIgnoresTransformations` where contracted, so they are constant-size at 150%/200% Windows scaling. The text overlay scales with zoom (scene-units) and clamps to [10, 28] viewport px. Re-test at 150%/200% as Phase 1 mandated.
- **IME support:** the inline editor (`QTextEdit`) + Inspector fields (`QTextEdit`) support IME (Japanese input method) — important because manga OCR text is Japanese and the user may correct it with a Japanese IME. `QGraphicsProxyWidget` + `QTextEdit` preserve IME (a `QGraphicsTextItem` would not, which is a secondary reason §15 chose the proxy widget).
- **Cursor:** the inline editor uses Qt's native text-edit cursor (`IBeamCursor` inside the editor). No new custom cursors in Phase 4.

## Open Questions for RESEARCH.md / Planner (surfaced by the UI researcher — not blocking this spec)

These are stack/implementation unknowns the UI-SPEC has *contracted around* (given a sensible default) but which RESEARCH.md (running next) or the planner should confirm:

1. **Vertical-text rendering in `QTextEdit` (D-06).** Qt's vertical writing-mode support is limited (`QTextOption.setTextDirection(Qt.Vertical)` exists but column-flow for real CJK vertical text may need a `QTextDocument`/`QTextBlock` layout override or a 3rd-party Qt vertical-text helper). UI-SPEC contracts the *behavior* (per-box toggle, `payload.vertical` preserved, editor flips orientation); RESEARCH confirms whether `QTextEdit`'s native vertical mode is sufficient or a custom paint path is needed. If vertical proves non-trivial, the fallback is: horizontal editor always, `payload.vertical` preserved as metadata only (the toggle becomes a no-op in v1 with a "coming soon" tooltip — defer the vertical *editor* without deferring the vertical *metadata*).
2. **Outlined-text rendering performance (D-11).** The multi-pass `QPainter` outline technique (draw text N times offset) can be slow for many boxes at low zoom. The `QGraphicsDropShadowEffect` alternative is cheaper but softer. RESEARCH confirms which is performant for a page with 20-50 boxes. UI-SPEC contracts the *look*, not the mechanism.
3. **Text-overlay scene-units scaling + zoom clamp (D-11).** The [10px, 28px] viewport clamp requires the executor to switch between scene-units rendering (normal zoom) and `ItemIgnoresTransformations` fallback (extreme zoom). RESEARCH confirms Qt's behavior at the transition points (does the text "jump" at the clamp boundary? a smooth interpolation may be needed).
4. **Reading-order auto-number algorithm thresholds (D-15/D-16).** The column-bucketing + per-column-top-to-bottom sort needs thresholds (column-detection tolerance, overlap handling). CONTEXT Claude's Discretion; RESEARCH picks the algorithm + thresholds against real manga pages.
5. **The `edited` flag's home (D-04).** On the recognized-text field, derived from diff, or on the box model — CONTEXT Claude's Discretion, planner decides. UI-SPEC contracts only its *effect* (silent overwrite when false, confirm when true).
6. **Parser batch-undo granularity (§20).** One BOXES entry per matched box vs one batch entry for the whole Load Translations apply — planner picks; UI-SPEC notes one batch entry is simpler.
