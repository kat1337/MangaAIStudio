## Spacing Scale

Inherited unchanged from Phase 1 (xs 4 / sm 8 / md 16 / lg 24 / xl 32 / 2xl 48 / 3xl 64). All applied via layout `setSpacing()` / `setContentsMargins()` / QSS padding, multiples of 4.

**Phase 9 exceptions (fixed geometric values, declared here so they are not invented later — same discipline as Phase 1's 1px cursor / 3px progress bar):**

| Value | Usage | Rationale |
|-------|-------|-----------|
| **44px** | Tools-strip fixed width (`setFixedWidth`) | Comfortable column for 36px buttons + 4px side padding; on the 4-grid. [RESEARCH A4] |
| **36×36px** | Each strip `QToolButton` square hit target | Icon-only buttons need a real click target; 36 = 32 + 2×2 border/padding budget. |
| **20×20px** | Icon render size inside strip buttons (`QIcon` actual size / `setIconSize(QSize(20, 20))`) | Reads cleanly at strip scale; crisp downscale from the 24px viewBox. [RESEARCH code example] |
| **24×24px** | SVG viewBox of each bundled icon asset | Asset coordinate space (on the 4-grid); Qt scales to the 20px render size. |
| **28px** | Collapsible-section header row minimum height (`setFixedHeight(28)` or QSS min-height) | Matches the `_detection_section_header` compact-row rhythm (12px label + 8px vertical padding). |
| **1px** | Divider between the two strip groups (`QToolBar.addSeparator()`) and between stacked sections (`border-bottom` on each section) | Inherited divider token `#3a3a42`. D-04 requires the strip group divider. |
| **0** | Central container layout margins + spacing (`setContentsMargins(0,0,0,0)`, `setSpacing(0)`) so strip and canvas sit flush | Probe-verified skeleton; the strip's own QSS provides its visual edge. |

Section body internals inherit their source rhythm verbatim (detection-settings form rows, brush slider↔spinbox gap xs=4, InspectorPanel sm margins) — relocation does NOT re-space them.

## Color

Phase 1's palette is inherited unchanged: Dominant `#232328` (60%), Canvas matte `#0b0b0e`, Secondary `#2d2d33` (30%), Divider `#3a3a42`, Text primary `#e8e8ea`, Text muted `#9a9aa2`, Destructive `#c0392b`, Error banner `#7a1f1f`/`#ffffff`. All semantic surface colors (mask red, preview cyan pen/fill, box origin green/amber, border-state palette) are untouched — this phase changes chrome arrangement only.

**Accent `#00d4ff` reserved-for list — UPDATED for the reworked chrome (relocation, not expansion):**

1. **Active tool highlight — now lives on the STRIP:** the checked strip tool button renders `border: 1px solid #00d4ff` on its `:checked` state (exact pattern of `_TOOLS_QSS` QToolButton:checked and curves_dialog.py:102). The icon glyph itself stays neutral `#e8e8ea` — the border is THE highlight [RESEARCH A3].
2. Selected page row in the sidebar (bg tint `rgba(0,212,255,0.18)` + 2px left border) — unchanged.
3. Keyboard focus outline (`:focus`) on every interactive widget — unchanged; strip buttons and section headers included.
4. Progress-bar fill (determinate + indeterminate) — unchanged.
5. The "running" state indicator on Detect Text / Inpaint — unchanged (now mirrored onto the strip buttons via default-action tracking).
6. The "Eraser" mode label color while erasing — unchanged.
7. `QPushButton:default` accent border in dialogs (inherited Phase 5 use) — unchanged.

Accent is NEVER used for: section headers or chevrons (muted/text-primary only), collapse affordances, dividers, body text, mask content, window chrome. The Edit-section buttons are plain text `QToolButton`s in secondary chrome — NO accent except focus outline.

**Icon glyph color (NEW, declared):** all 8 SVG icons draw their strokes in `#e8e8ea` (text primary) on transparent background — monochrome so the accent checked-border reads as the sole active signal [RESEARCH A3]. Disabled state relies on Qt's automatic `QIcon.Disabled` greying plus the QSS disabled button background `#25252b` (existing token).

### 38. Unified side panel · UI-01, UI-02, UI-04 · D-01/D-02/D-03 · (`main_window._build_docks` rework + new `gui/side_panel.py`)

- **One dock replaces two:** today's tabified `dock_tools` + `dock_inspector` pair (main_window.py:299-334) is replaced by a single right-side `QDockWidget` titled **"Panel"** whose body is a vertical stack of four independently-collapsible sections. QToolBox is FORBIDDEN (single-current-item semantics violate UI-01's independence requirement).
- **CollapsibleSection mechanism:** custom header+body widget — a checkable `QToolButton` header row (title text + ▸/▾ arrow indicator) whose `toggled` shows/hides its body via plain `setVisible` (NO animation — QPropertyAnimation on heights fights QScrollArea sizing). Headers styled per the Section-header typography role (12px/600/muted), min-height 28px, 1px `#3a3a42` bottom divider per section.
- **Section order (D-02, workflow order):** Detection settings → Brush → Typesetting → Edit. Bodies: detection-settings form moves from `ToolsPanel._build_detection_settings_section` (tools_panel.py:386-559); Brush rows move from the ToolsPanel brush block (slider↔spinbox blockSignals mirror pairs verbatim); Typesetting body IS the existing `InspectorPanel` content (text fields + Style section + inpaint override combo, Mixed-state machinery intact); Edit body is new (§40).
- **Scroll-wrap rule A11 carries over:** the panel body keeps ONE vertical-only `QScrollArea` wrap around all four sections (`setWidgetResizable(True)`, horizontal scrollbar always off — tools_panel.py:149-171 pattern). Never nest per-section scroll areas.
- **Collapse persistence (D-02):** each section's expanded state persists across sessions via QSettings keys `sidePanel/detectionExpanded`, `sidePanel/brushExpanded`, `sidePanel/typesettingExpanded`, `sidePanel/editExpanded`. Written on every toggle; read after build with the tolerant bool parse (`"true"/"1"/"yes"/"on"` accepted — `_read_detect_boxes_mode` precedent, main_window.py:3003-3006). **Defaults on first run: all four EXPANDED** [RESEARCH A2].
- **Panel-header toggle (UI-02):** a chevron `QToolButton` ("Toggle panel", ▸/▾) sits at the very top of the panel, above the sections. Clicking it collapses/expands the whole scroll-area body while the dock STAYS DOCKED (avoids re-fighting QMainWindow dock visibility state) [RESEARCH A1]. Toggle state is session-transient — NOT persisted (only section collapse is contracted for persistence, D-02). The View menu gains one **"Toggle Panel"** action that drives the same toggle, replacing both old dock toggle actions.
- **Signal survival contract:** every relocated control keeps its existing signal EXACTLY — `tool_changed`, `brush_size_changed`, `detect_boxes_changed`, `dilation_changed`, `std_dev_threshold_changed`, `masker_params_changed`, Inspector style signals. Tests emit these directly off the widgets (e.g. tests/test_gui_detection_boxes.py emits `tools_panel.dilation_changed`) — relocation must not rename or re-route them.
- **Enablement gating:** section controls keep mirroring `_refresh_action_states` gating (page-open / op-running) exactly as they do today. The Edit-section buttons inherit this for free via default-action binding (§40).

### 39. Vertical tools strip · UI-03 (as corrected by D-05) · D-04/D-06 · (new central-widget container in `main_window.py`)

- **Placement (probe-verified constraint):** the canvas stops being the direct central widget (`setCentralWidget(self.canvas)`, main_window.py:135). It is wrapped in a container QWidget whose QHBoxLayout is `[strip][canvas]`, giving left→right **Pages | strip | canvas | side panel** (D-05). NEVER use `addToolBar(Qt.LeftToolBarArea)` — QMainWindow lays toolbar columns OUTSIDE dock columns and `setCorner()` cannot fix it (strip would land left of Pages) [RESEARCH probe results].
- **Strip construction:** an embedded vertical `QToolBar` (`setOrientation(Qt.Vertical)`, `setFixedWidth(44)`, icon size 20px) or an equivalent plain-QWidget column of `QToolButton`s — executor's choice; the LOOK and behavior are the contract.
- **Contents top→bottom (D-04):** the 6 exclusive tools — Move/Pan (V) · Brush (B) · Rectangle (R) · Lasso (L) · Eraser (E) · Crop (G) — then a **divider**, then Detect Text (D) and Inpaint (C). Eight buttons total, icon-only with tooltips.
- **Active-tool sync (WR-02 contract — MUST NOT regress):** strip buttons mirror the standalone checkable window actions via `setDefaultAction` + `setCheckable(True)` (the `_make_tool_toolbar_button` pattern, main_window.py:4250-4266). The exclusive `QActionGroup` holds EXACTLY the strip's own tool actions; window actions stay outside it and remain driven explicitly by `set_active_tool`'s blockSignals loop (06 D-10). Exactly ONE `tool_changed` emission per selection from every entry path (click / keyboard V-B-R-L-E-G / menu / programmatic). Never connect both `triggered` and `toggled`.
- **Checked visual:** accent border per the Color contract (reserved use #1); unchecked buttons sit flat on Secondary `#2d2d33` with 1px `#3a3a42` border; hover lightens to `#34343c` (existing token).
- **Detect Text / Inpaint buttons:** plain (non-checkable) default-action buttons; running-state spinner/disabled mirrors the action state as the top-toolbar buttons do today.
- **Icons:** see §Icon Asset Contract below.

### 40. Edit section body · UI-05 · D-08/D-09 · (new section body binding existing QActions)

- **Six buttons bound via `setDefaultAction` to the LIVE window actions:** Curves… (`action_curves`), Crop… numeric dialog (`action_crop_dialog`), Resize… (`action_resize`), Rotate 90° CW / CCW / 180° (the three rotate actions). Rendered as a 2-column grid of text `QToolButton`s (labels per §Copywriting), secondary chrome, sm (8px) gaps.
- **Zero new logic:** enabled-state gating comes free — `_refresh_action_states` already recomputes those actions on every page/op event, and default-action buttons track enabled/disabled/tooltip automatically.
- **The Crop TOOL stays a strip button** (G, armed on-canvas rect); only the numeric Crop… dialog entry lives in Edit (D-08).
- **No Levels entry** — superseded by Curves (Phase 6 D-01); UI-05's "levels" reads as the curves dialog.
- **Menu slimming (D-09):** Rotate ▸ / Curves… / Resize… leave the Tools menu's Image section; Crop… leaves the Edit menu. The QAction objects stay ALIVE as state holders (the `action_detect_boxes_mode` precedent) — removing menu membership only, never deleting actions or shortcuts.
- **Keyboard reachability audit (RESEARCH Pitfall 5 verified):** rotate/curves/resize/crop-dialog carry NO shortcuts today; tool shortcuts (V/B/R/L/E/G) and Detect/Inpaint (D/C) live on window-level actions independent of menus. Slimming menus therefore drops zero keyboard access. Any future `setShortcut` removal is out of contract.
