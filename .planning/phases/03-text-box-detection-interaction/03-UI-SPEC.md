> Visual and interaction contract for the Phase 3 text-box layer. Generated by
> gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **CRITICAL CONTEXT — PySide6 / Qt6 DESKTOP application, not a web app.** This
> contract extends the Phase 1 design system (see
> `01-cleaning-workspace/01-UI-SPEC.md`) with a new interaction layer —
> editable text boxes on top of the existing canvas. It speaks Qt, not CSS:
> `QGraphicsRectItem`, `QPen`/`QBrush`, `QAction`/`QActionGroup`, `QShortcut`,
> `QMessageBox`, `QPainterPath`, `QCursor`/`CursorShape`, QSS. Design tokens
> here are the source of truth for the executor.
>
> **Relationship to Phase 1:** this is a *delta + reaffirmation*. Every token
> not explicitly overridden below is inherited unchanged from the Phase 1
> contract (color palette, spacing scale, typography, Fusion style, dark
> QPalette, canvas matte `#0b0b0e`, mask overlay `rgba(255,0,0,0.63)`, accent
> `#00d4ff` and its 6 reserved uses). The one *intentional superset change* is
> the undo surface (D-11) — see §"Phase 3 Delta vs Phase 1" and Surface 13.

### D-09 color rationale (the locked decision the researcher was asked to specify)

**Detected = green `#5fd068`.**
1. **Canonical precedent:** PanelCleaner's own `visualize_textblocks` (`panelcleaner/comic_text_detector/utils/textblock.py:541`) draws detected `TextBlock` bboxes in green `(127, 255, 127)`. Phase 3 consumes those exact `TextBlock` objects, so green is the consistent, familiar encoding for "machine-detected box". `#5fd068` is a slightly muted, slightly cooler green that holds contrast on `#0b0b0e` (luminance contrast ≈ 6.5:1, well above the artwork-legibility bar) without the neon harshness of pure `(127,255,127)`.
2. **Semantic fit:** green universally reads as "system/default/auto" — exactly the boxes a re-detect would replace (D-03).
3. **No clash:** distinct hue from red (mask), cyan (accent), amber (user).

**User = amber `#f5a623`.**
1. **Distinct hue family:** amber is warm where green/red/cyan are cool-to-neutral — the user's boxes never blur into the mask overlay or the accent. Luminance contrast on `#0b0b0e` ≈ 7:1.
2. **Semantic fit:** amber reads as "marked by you / caution / yours to keep" — matches the D-03 rule that user boxes survive re-detect.
3. **No clash with the Phase 1 dashed-cyan preview:** the create-box drag reuses the existing `preview_item` (z=900) but is recolored amber so the user never confuses "drawing a mask rect" (cyan) with "drawing a user box" (amber). The two operations produce visually different previews in the same screen region.

**Accent `#00d4ff` is NOT used for boxes.** This preserves the Phase 1 reserved-for list (active tool, selected page row, focus outline, progress fill, running-op spinner, eraser-mode label) so the cyan stays meaningful. Boxes get their own two semantic hues.

## Interaction & Surface Contracts (Phase 3 — the new + changed surfaces)

> Phase 1 defined surfaces 1-9. Phase 3 adds surfaces 10-13 and **changes**
> surface 8 (undo). Each surface maps to ROADMAP Phase 3 success criteria and
> requirement IDs TEXT-01 / TEXT-03.

### Z-order on the scene (concrete, executor-authoritative)

```
z=0     image_item        (QGraphicsPixmapItem, bottom)
z=0     mask_item         (QGraphicsPixmapItem, above image — added after it)
z=100   box layer         (QGraphicsItemGroup / parent-less box items)
z=150   corner handles    (child QGraphicsRectItems of each box, explicit z)
z=850   empty-box-layer hint  (QGraphicsTextItem — below the preview)
z=900   preview_item      (QGraphicsPathItem — existing; cyan dashed for mask
                          tools, AMBER dashed during box-create)
z=1000  cursor_item       (QGraphicsEllipseItem — existing brush outline)
z=2000  empty-state text  (existing "No page open" stack — no page loaded)
```

Boxes sit **above the mask overlay, below the tool preview/cursor** (D-02/D-05). The create-box preview reuses `preview_item` (no new item) recolored amber, so mask-rect-create (cyan) and box-create (amber) never visually collide.

### 10. Text-box detection surface (extended) · TEXT-01 · (`gui/main_window.py:_on_detection_finished`)

- **Seam (the load-bearing change):** `_on_detection_finished` (line 1284) currently reads only `result["mask"]` and discards `blk_list`. Phase 3 adds `result["boxes"]` (the `blk_list` already returned by `TorchCTDModel.detect` via `adapters/torch_impl.py:104`) and, when **Detect Boxes** mode is on, builds one `BoxItem` per `TextBlock` (origin=`"detected"`) and adds it to the box layer.
- **One Detect action, one model pass (D-01):** the mode toggle only controls whether `blk_list` is surfaced — there is no second model call, no "Detect Boxes" action. Mode off = Phase 1 behaviour (mask only); mode on = mask + boxes.
- **Async + progress + error (inherited):** unchanged from Phase 1 surface 5. Box rendering happens in the main-thread `_on_detection_finished` handler (thread-safe per T-01-07); no Qt mutation off the GUI thread.
- **Box layer auto-shows on first detection:** completing a Detect with mode on sets the box-overlay toggle to checked (the boxes the user just asked for are visible). The user can toggle it off (`Shift+M`).

### 11. Box layer + overlay toggle · D-02 · (`gui/canvas.py` + `_build_view_menu`)

- **Layer:** a `QGraphicsItemGroup` (or parent-less item set) at z=100, toggled via `setVisible(bool)`. Independent of `mask_item` visibility (D-02: showing/hiding one does not affect the other).
- **View → Toggle Box Overlay** (`Shift+M`): checkable `QAction` placed in `_build_view_menu` immediately **after** `Toggle Mask Overlay` (they are sibling layer toggles). Checked state mirrors `box_layer.isVisible()`. Enabled iff a page is open. Shortcut `Shift+M` (M is taken by the mask overlay; B/R/L/E/V by tools; D/C by detect/inpaint; P by preview — `Shift+M` is the mnemonic "the other overlay" and conflicts with nothing).
- **Hidden = not interactable (D-07):** when the layer is `setVisible(False)`, box hit-testing is skipped entirely (boxes neither select nor block mask painting).

### 12. Box object, selection, move, resize, delete, create · TEXT-03, D-05/D-06/D-07/D-08/D-12/D-13 · (`gui/canvas.py` + new `BoxItem`)

This is the heart of the phase. All values are executor-authoritative.

#### 12a. BoxItem (`QGraphicsRectItem` subclass)

- **Geometry:** `QRectF(x1, y1, x2-x1, y2-y1)` in scene/image-pixel coords, from `TextBlock.xyxy = [x1,y1,x2,y2]` (ints). On re-parenting to the box layer, z=100.
- **Flags:** `ItemIsSelectable | ItemIsMovable | ItemSendsGeometryChanges`. (Move + the undo hook on geometry change come from these; selection state drives handle visibility.)
- **Pen (origin-coloured, D-09):**
  - Detected, unselected: `QPen(QColor("#5fd068"), 2)`, `Qt.SolidLine`.
  - User, unselected: `QPen(QColor("#f5a623"), 2)`, `Qt.SolidLine`.
  - Selected (either origin): same hue, **3px**.
- **Brush:** transparent (`Qt.NoBrush`) when unselected; `QBrush(QColor(r,g,b, 31))` (≈0.12 alpha, hue-matched) when selected — the selection fill tint.
- **Selection pen override:** disable Qt's default dashed selection outline (`QGraphicsRectItem.paint` override, or `item.change(SelectedChange)` pen swap) so the origin-coloured solid border is the sole selection signal plus the handles + tint. The CONTEXT's "native Qt selection dashed outline comes free" is the *mechanism* (selection state); the *look* is ours.
- **Origin flag:** `box.origin ∈ {"detected", "user"}` drives the pen hue. (D-03.)
- **No inline text** (Phase 4). The `TextBlock` payload (`text`/`translation`/`vertical`/`language`) is carried on the item as data, untouched, for Phase 4/5.

#### 12b. Corner resize handles (D-05/D-06)

- **Four child `QGraphicsRectItem`s**, one per corner (TL, TR, BL, BR), `setParentItem(box)`, explicit z=150 so they render above the border.
- **Size:** 8×8 **viewport** px, `ItemIgnoresTransformations` enabled → constant grab target at any zoom (see Spacing exceptions). Position recomputed on every box geometry change + every `zoom_changed` (the canvas already emits this signal).
- **Fill:** solid box-border hue (green for detected, amber for user). **Outline:** 1px `#0b0b0e` (matte) for separation from artwork.
- **Shape:** square (not circle) — corners are corner-shaped; squares read as "resize anchor".
- **Visibility:** **shown ONLY on the selected box** (D-08 single-select; handles on all boxes is clutter). Hidden when no box is selected.
- **Resize behaviour (D-06):** drag a corner → both adjacent edges move (corner-drag resize). Min size 8×8 scene px enforced on release (clamp, not cancel). Cursor over a handle: `SizeFDiagCursor` (TL/BR) / `SizeBDiagCursor` (TR/BL) — Qt's native diagonal-resize cursors, the natural affordance. Edges are NOT independently resizable in v1 (CONTEXT §deferred).

#### 12c. Selection affordance (D-08 single-select)

| State | Border | Fill | Handles | Cursor over box |
|-------|--------|------|---------|-----------------|
| Unselected, box layer visible | 2px solid (hue) | transparent | hidden | `SizeAllCursor` (move affordance) |
| Hover, unselected | (unchanged — no hover colour shift; keeps the artwork calm) | transparent | hidden | `SizeAllCursor` |
| Selected | 3px solid (hue) | `rgba(hue, 0.12)` | 4 corners shown | `SizeAllCursor` (body) / `SizeFDiagCursor`·`SizeBDiagCursor` (over a handle) |

Selection is the explicit signal; there is no hover colour shift (Phase 1's principle: keep the artwork the sole saturated surface — hover flashes would violate it). **Deselect:** click on empty canvas (box layer visible, no Alt held) OR press `Esc`.

#### 12d. Hit-testing + dispatch (D-07 — the no-new-tool rule)

Slots into the existing `EditorCanvas.mousePressEvent` (canvas.py:758) **before** the mask-tool branch. Order:

1. Pan (middle / Space+left) — unchanged, highest priority.
2. **Box layer visible?** → `scene.itemAt(scene_pos)` (or `items()` filtered to box layer):
   - Hit a **corner handle** (of the selected box) → begin **resize**.
   - Hit a **box body** → **select** it (deselect any other) + begin **move** drag. (Works in ANY tool mode — D-07: boxes always interactive.)
   - Hit **empty canvas**:
     - `Alt` held + left-drag → begin **create-box** drag (12e).
     - else → **deselect** the current box, then **fall through** to the existing mask-tool dispatch (left-click + active mask tool → paint; Move tool → nothing). This preserves Phase 1 mask painting exactly.
3. Box layer hidden → skip box hit-testing entirely; existing dispatch unchanged.

**Anti-pattern honored:** no 6th tool in `ToolsPanel`'s `QActionGroup` (D-07). `ToolMode` enum (`core/mask_editor.py`) is unchanged for v1. Box interaction is tool-agnostic.

#### 12e. Draw-to-create a user box (D-13 — the gesture decision)

**Gesture: `Alt` + left-drag on empty canvas** (box layer visible), in ANY tool mode.

Rationale (least-surprising given D-07's "boxes always interactive"):
1. **Modifier-gated ⇒ never collides with mask painting.** Brush/Rect/Lasso drags still paint (Alt is not Shift-the-eraser, not Ctrl-the-zoom, not Space-the-pan). Alt is the only clean single modifier left, and bare Alt+drag conflicts with nothing (Alt+Z mask-undo requires Z).
2. **Uniform across tools** ⇒ more discoverable than "only in Move mode". Alt always means "create a box now", whether the user is in Move, Brush, Rect, Lasso, or Eraser.
3. **Convention:** Alt is the established "alternate action" modifier in editors.

**Create-drag feedback:**
- Cursor → `CrossCursor` the moment Alt is held (create mode "armed"), even before drag starts.
- During drag: the existing `preview_item` (z=900) shows an **amber dashed** rect `QPen(QColor(245,166,35,200), 2, Qt.PenStyle.DashLine)` from drag-start to cursor (recoloured from the mask-rect cyan so the two operations are visually distinct).
- On release: if the rect ≥ 8×8 scene px → create a `BoxItem` with `origin="user"` (empty — no text; TEXT-02 fills it in Phase 4), push a `box create` record onto the BOXES stack (D-10), select the new box, emit undo feedback. If < 8×8 → no-op (not a zero-area box).
- `preview_item` is cleared on release (same as Phase 1 mask-rect commit, canvas.py:893).

**Discoverability:** Alt+drag is hidden by nature. It is anchored by (a) the empty-box-layer hint overlay (§12f) and (b) the `Toggle Box Overlay` tooltip. No separate menu/toobar button is added (that would approximate a 6th tool).

#### 12f. Empty-box-layer state (the discoverability anchor)

When the box layer is ON and **zero** boxes exist on the page (no detection run, or all deleted): show a `QGraphicsTextItem` at z=850, centred horizontally near the top of the page (y ≈ 48 scene px from the top edge — Phase 1's `2xl` inset):

> **"No text boxes yet. Alt+drag on the page to draw one, or Tools → Detect Text (D)."**

12px Regular, `#9a9aa2` (muted). Hidden the moment any box exists OR the layer is toggled off. (Mirrors Phase 1's empty-state philosophy: tell the user the next action.)

#### 12g. Delete (D-12 — silent, immediate)

- **Trigger:** `Delete` key (`Qt.Key.Key_Delete`) when a box is selected. (`Backspace` alias optional.)
- **Behaviour:** remove the selected `BoxItem` immediately, no dialog. Push a `box delete` record (with the box's last geometry + origin + payload) onto the BOXES stack. Deselect. Emit the transient status flash **"Deleted box — press Ctrl+Z to restore."** (non-blocking; "silent" means no modal/confirm, not no feedback).
- **Contrast:** NOT styled with the destructive `#c0392b` — boxes are cheap to undo (D-12), unlike Clear Mask which confirms.

### 13. Undo/redo surface (CHANGED — D-10/D-11) · FLOW-02 + TEXT-03 · (`core/history_manager.py` + toolbar/menus)

> **This surface supersedes Phase 1 surface 8.** Phase 1 contracted **2 logical
> stacks** (MASK + IMAGE) surfaced as **4 toolbar buttons** + **4 shortcuts**
> (`Ctrl+Z`/`Ctrl+Shift+Z` image, `Alt+Z`/`Alt+Shift+Z` mask). Phase 3 adds a
> **3rd stack BOXES** (D-10) and **merges the pop order into a unified
> chronological timeline** (D-11) — one shortcut pair over all three stores.
> The per-type snapshot semantics are preserved (Phase 1 D-01-06 / CONTEXT
> D-10: "do NOT collapse Phase 1's two stacks into one"); only the *pop order*
> and the *UI surface* unify.

- **Three underlying stacks (D-10):** MASK (QImage snapshots, inherited), IMAGE (`(x,y,patch)` tuples, inherited), **BOXES (NEW: full per-page boxes-list snapshot per op — cheap; matches Phase 1's full-snapshot shape per CONTEXT D-10/Claude's Discretion).** BOXES entries are `(op_type, box_id, before_bbox, after_bbox, origin, payload_ref)`.
- **Unified timeline (D-11):** `Ctrl+Z` pops the most-recent-by-timestamp entry across all three; `Ctrl+Shift+Z` redoes likewise. One shortcut pair, chronological, no stack-switching exposed.
- **Toolbar (CHANGED):** collapses from 4 buttons to **2** — `[Undo][Redo]` (single pair, no inner divider, no mask/image split). Tooltips: `"Undo last action (Ctrl+Z)"` / `"Redo (Ctrl+Z)"`. The dynamic status tip shows the next op type (e.g. `"Undo: box resize"`).
- **Edit menu (CHANGED):** collapses to **2 items** — `Undo (Ctrl+Z)`, `Redo (Ctrl+Shift+Z)`. The Phase 1 `Undo Mask`/`Redo Mask` (`Alt+Z`/`Alt+Shift+Z`) items are **removed** (subsumed).
- **Shortcuts (CHANGED):**

  | Action | Shortcut | Phase 1 | Phase 3 |
  |--------|----------|---------|---------|
  | Undo (unified) | `Ctrl+Z` | Undo Image | **Undo — any stack, most-recent first** |
  | Redo (unified) | `Ctrl+Shift+Z` | Redo Image | **Redo — any stack, most-recent first** |
  | ~~Undo Mask~~ | ~~`Alt+Z`~~ | — | **removed** (subsumed by unified Ctrl+Z) |
  | ~~Redo Mask~~ | ~~`Alt+Shift+Z`~~ | — | **removed** (subsumed) |

- **Which-stack-was-popped indication (D-11 open question, resolved):** the status-bar left field shows a transient **"Undo: {op}"** / **"Redo: {op}"** message (§Copywriting) for ≈3 s after each undo/redo, naming the op type (`mask edit` / `inpaint` / `box create|move|resize|delete`). This is the only visible signal of which store the unified pop touched — necessary because the user can no longer target a stack by modifier.
- **Disabled state:** Undo disabled when all three undo lists are empty; Redo disabled when all three redo lists are empty.
- **Per-page reset (inherited seam):** switching pages resets all three stacks (Phase 1's `reset_history` on `on_page_selected`). BOXES follows the Phase 2 D-11 per-page persistence seam (save outgoing page's boxes, `.copy()`-detach at both boundaries, restore incoming) — UI-identical to mask persistence; the planner designs the `ImageFile.boxes` slot.

### Per-page box persistence (D-11 of Phase 2, mirrored) · seam note

UI-invisible. Boxes persist per-page across navigation exactly as masks do (Phase 2 D-11 / T-02-04): save on page-leave, restore on page-select, `.copy()` at both boundaries. The `ImageFile` dataclass gains a `boxes` slot mirroring its `mask` slot (CONTEXT Claude's Discretion — planner confirms shape). No new UI for this; the box count in the status bar reflects the restored state.

## Accessibility & Platform Notes (Phase 3 delta)

- **Contrast:** detected green `#5fd068` and user amber `#f5a623` on the `#0b0b0e` matte both exceed ≈6.5:1 luminance contrast — well above the bar for graphical objects (WCAG 1.4.11 non-text contrast ≥3:1). Box borders remain distinguishable for colour-blind users because the two hues also differ in *luminance* (amber is markedly brighter) and in *style context* (selected vs unselected adds handles + fill tint, not hue alone). The origin distinction is reinforced by the status-bar count ("· {d} detected, {u} user").
- **Keyboard:** all Phase 3 actions are keyboard-reachable — Detect (`D`), toggle overlay (`Shift+M`), undo/redo (`Ctrl+Z`/`Ctrl+Shift+Z`), delete (`Delete`), deselect (`Esc`). The one mouse gesture — Alt+drag to create — has no full keyboard equivalent in v1 (a future `Edit → Add Box` with size dialog could close this; deferred — not a TEXT-01/03 requirement). Selecting/moving a box via keyboard arrow-keys is a v2 polish candidate, not contracted here.
- **Focus:** the accent `#00d4ff` 2px focus outline (Phase 1 reserved use #3) continues to apply to all toolbar/menu widgets. Box selection on canvas uses the origin-coloured border + handles, NOT the accent (accent stays reserved).
- **High-DPI:** corner handles use `ItemIgnoresTransformations` + 8 viewport px, so they are a constant grab target at 150%/200% Windows scaling (the handle's screen size tracks the viewport, not the scene). Re-test at 150%/200% as Phase 1 mandated.
- **Cursor size:** the system cursor is unchanged; box cursors (`SizeAllCursor`, `SizeFDiagCursor`, `SizeBDiagCursor`, `CrossCursor`) are Qt standard sizes.
