GAP 3 (test 3): the third Ctrl+Z wipes ALL detected boxes. Root cause (UAT,
diagnosed, reproduced live): _build_detected_boxes explicitly pushes a
`pre_detection_snapshot` at Step 5 (main_window.py:1633). At detect-time the
layer is empty, so that snapshot is `[]`. After [detect, move] the BOXES stack
= [0-boxes, 3-boxes]; undo#2 pops the 3-box pre-move snapshot (correct —
reverts the move); undo#3 pops the 0-box pre-detection snapshot -> restores []
-> ALL detected boxes vanish. The before-state convention made the INITIAL
detection undoable, which is never desired mid-session.

Fix (per UAT fix_direction): make detection a NON-undoable seeding event.
Detection establishes the baseline WITHOUT pushing an empty entry; the first
real user edit then pushes against that baseline. This mirrors how mask
strokes are individually undoable but the initial mask presence (from a detect)
is not. The explicit `self.history.push_boxes_state(pre_detection_snapshot)`
call at main_window.py:1633 is REMOVED; the `_suppress_boxes_push` guard at
Step 3 already suppresses the set_boxes emission, so after removing the
explicit push the detection apply produces NO boxes stack entry at all.

GAP 4 (test 4, partial): a moved box's position resets across a page
round-trip (user boxes too). The UAT flags this as SHARING the before-state
root cause and lists two candidates to confirm by live probe: (a)
boxes_snapshot/current_box reads a cached PageBox.box not the live rect
post-move; (b) the CR-01 before-state snapshot is written back as authoritative
state at page-switch. Task 1 CONFIRMS the real cause with a probe driving the
live move-commit path + a real on_page_selected round-trip BEFORE coding the
fix, because the UAT explicitly marks this `diagnosed: partial`.

    Candidate (a) is FALSE on static read: canvas.boxes_snapshot()
    (canvas.py:1230-1255) calls `item.current_box()` which materializes a fresh
    Box from `self.rect()` at call-time (box_item.py:268-285) — NOT from the
    stored PageBox.box. Candidate (b) is the more likely culprit: the move-commit
    captures a before-snapshot into `_boxes_interaction_start_snapshot` and emits
    it; if that snapshot object is held by reference and re-read at page-switch,
    the stale pre-move geometry wins. The fix direction is to ensure (1)
    boxes_snapshot ALWAYS materializes from live rect (already true — verify, do
