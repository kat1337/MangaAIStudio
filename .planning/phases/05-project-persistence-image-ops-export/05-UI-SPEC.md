# Phase 5 — UI Design Contract (Project Persistence, Image Ops & Export)

> Visual and interaction contract for the Phase 5 "resumable workspace" layer.
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **CRITICAL CONTEXT — PySide6 / Qt6 DESKTOP application, not a web app.** This
> contract extends the Phase 1 + Phase 3 + Phase 4 design systems (see
> `01-cleaning-workspace/01-UI-SPEC.md` (approved 2026-07-12),
> `03-text-box-detection-interaction/03-UI-SPEC.md` (approved 2026-07-25),
> `04-ocr-recognition-text-editing/04-UI-SPEC.md` (approved 2026-08-08)). It
> speaks Qt, not CSS: `QDialog`, `QFileDialog`, `QMessageBox`, `QSlider`,
> `QSpinBox`, `QDoubleSpinBox`, `QComboBox`, `QCheckBox`, `QFormLayout`,
> `QAction`, `QShortcut`, `QGraphicsPathItem`. Design tokens here are the
> source of truth for the executor.
>
> **Relationship to Phases 1–4:** this is a *delta + reaffirmation*. Every
> token not explicitly overridden below is inherited unchanged (color palette,
> spacing scale, typography, Fusion style, dark QPalette, canvas matte
> `#0b0b0e`, mask overlay `rgba(255,0,0,0.63)`, accent `#00d4ff` and its
> reserved uses, detected green `#5fd068` / user amber `#f5a623`, text overlay
> `rgba(232,232,234,0.85)`, the 3-stack unified Ctrl+Z undo from Phase 3
> surface 13, the dialog QSS pattern from `load_translations_dialog.py`).
>
> **The phase's three user-visible additions:** (1) the project layer —
> Save/Open Project… (`Ctrl+S`/`Ctrl+O`, dirty `*` title, Save/Discard/Cancel
> prompt, Recent Projects, chapter-climb dialog — CONTEXT D-07/D-08/D-09);
> (2) the four image ops — Rotate 90° steps, Canvas Crop tool (the **6th
> tool**, D-11), Levels dialog, Resize dialog (D-10…D-14), all silent +
> one-Ctrl+Z undoable; (3) the `_ocr.json` exporter — single-page + batch
> (D-19…D-22). Everything the phase serializes already exists in memory
> (masks, boxes, text) or on the canvas (current image) — Phase 5 adds **no
> new models and no re-running of detection/OCR**.

## Spacing Scale

Inherited unchanged from Phase 1 (4 / 8 / 16 / 24 / 32 / 48 / 64). Phase 5 adds **no** new layout spacing tokens. The new dialogs use the inherited form rhythm: `QFormLayout` row spacing `sm` (8px), dialog contents margins `md` (16px), section gaps `lg` (24px) — matching `load_translations_dialog.py`.

**Phase 5 exceptions (non-spacing geometric/semantic values, declared here so they are not "invented" later — same discipline as Phase 1's 1px cursor / 3px progress-bar, Phase 3's 8px handle, Phase 4's badge):**

| Value | Usage | Rationale |
|-------|-------|-----------|
| **8×8 scene px** | Minimum crop-rect size (width and height, enforced on crop-drag release) | Matches the Phase 3 8×8 minimum-box-size constant verbatim — a crop smaller than the box minimum is a no-op, not a degenerate edit. |
| **2px** | Crop preview border (dashed, `rgba(0,212,255,0.78)` — the existing `preview_item` pen) | Reuses the inherited mask-rect/lasso dashed preview geometry; the crop rect is a "define a region" gesture just like the mask rect, so it shares the pen. The dim-out overlay (below) is what makes it read as *crop*, not mask. |
| **0.45 alpha** | Crop dim-out overlay fill (`rgba(0,0,0,0.45)`) — darkens everything OUTSIDE the crop rect while dragging | The universal crop affordance (Photoshop/Krita/GIMP all dim the discarded area). Deliberately darker than the 0.24 preview fills and lighter than opaque black: the artwork stays visible enough to judge the crop, clearly dimmed enough to read as "will be removed". Matte-black hue (no saturation) per the "artwork is the sole saturated surface" principle. |
| **1 px** | Crop dim-out overlay border inset (the dim rects meet the crop edge exactly; no gap, no overlap) | Pixel-exact dim boundary so the crop edge is unambiguous at 100% zoom. |
| **±0.01** | Levels gamma step (QDoubleSpinBox singleStep) | Fine-grained enough for 1.00…4.00 gamma corrections; the slider is log-scaled (see §Surface 25). |
| **10° / 1°** | Rotate action granularity — none: rotation is 90°/180° steps ONLY (D-10, locked) | No arbitrary-angle UI ships in v1 (deferred). The three menu actions are the entire rotate surface. |

## Open Questions for RESEARCH.md / Planner (surfaced by the UI researcher — not blocking this spec)

These are stack/implementation unknowns the UI-SPEC has *contracted around* (given a sensible default) but which RESEARCH.md (running next) or the planner should confirm:

1. **`Ctrl+O` remap confirmation (D-07 vs Phase 1).** D-07 explicitly assigns `Ctrl+O` to Open Project…, colliding with Phase 1's Open Image… (`main_window.py:261`). The spec resolves it as "newest user decision wins; remove the old binding" — the planner must confirm this resolution (or propose a different free key) BEFORE wiring, and the executor MUST remove the stale binding (never leave two actions bound to Ctrl+O).
2. **Geometry-op undo record shape (CONTEXT Claude's Discretion).** One Ctrl+Z must reverse image + mask + boxes together — combined record vs paired-stack push with a merge rule; the planner picks the least-surprising unified-timeline behavior (Phase 3 D-11). UI contract: one press per op.
3. **Crop-tool armed-rect persistence.** The spec contracts "drag, then Enter to apply" (rect stays armed after release). Confirm this matches the canvas's existing event-dispatch structure (the mask-rect commits on release; the crop path needs an armed state + a consume of subsequent Enter/Esc).
4. **Levels live preview with a modal dialog.** The spec contracts in-place live preview while a modal `QDialog.exec()` runs (Qt's nested event loop repaints the canvas behind the dialog). Confirm the canvas repaint path is safe mid-modal (no timers/workers involved — it is a synchronous numpy transform, so it should be).
5. **`cleaned/` creation for altered-page JSON export (D-22).** The spec contracts creating `cleaned/` if missing. Confirm the Phase 2 batch runner's folder-creation helper is reusable (or accept a `os.makedirs(exist_ok=True)`).
6. **Batch Export OCR JSON threading.** Model-free serialization is fast; the planner decides Worker vs inline (CONTEXT Claude's Discretion). The UI surface (progress bar + status) is contracted for the Worker path; an inline path only needs the completion flash.
