<objective>
Close UAT test 2 (MAJOR, diagnosed): the corner resize handle is practically
unhittable on real artwork. The 8x8 viewport-px CornerHandle is centred ON the
box corner, so ~half sits outside the box (reads as background/pixmap -> no-op)
and the inner half overlaps the BoxItem body (-> triggers a move, not a resize).
A grid probe of scene.itemAt around the BR handle at 1:1 zoom returns
CornerHandle only in a ~6x6 central pocket; BoxItem/pixmap for +-6px offsets.

Fix (per UAT fix_direction): enlarge the effective HIT area WITHOUT enlarging
the visible handle, by overriding CornerHandle.shape() to return a ~18px rect
centred on the handle's corner point. The paint/boundingRect stay 8x8 (no
visual change); only the hit shape grows. This is the standard Qt Graphics
View technique and is localised to the handle — the canvas hit-test dispatch
(canvas.py:859-864) is already correct in scene coords and is NOT changed.

This gap is INDEPENDENT of the undo/baseline convention (Gaps 2/3/4) — it is
purely hit-target geometry (D-06/D-08).

Purpose: Restore TEXT-03's resize affordance so a user can correct detection
errors by dragging box corners (the whole point of the editable-box layer).
Output: Larger hit target on CornerHandle + a geometry regression test.
</objective>
