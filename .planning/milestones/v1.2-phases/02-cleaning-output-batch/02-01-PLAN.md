## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| numpy result → filesystem | Worker/result numpy crosses into `save_image_optimized` and is written to a user- or batch-derived path. |
| original file → output metadata | `save_image_optimized` opens the original to read mode/DPI; a crafted original could carry malformed metadata. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | save_image_optimized path arg | medium | mitigate | The Export save path is OS-validated via `QFileDialog.getSaveFileName` (Plan 04, T-01-01 sibling). The batch output dir is DERIVED from the open folder (`source.parent / "cleaned"`, D-06/D-07), never user-supplied — `save_image_optimized` itself calls `path.parent.mkdir(parents=True, exist_ok=True)` but never derives a path from the original, so there is no traversal vector in this module. |
| T-02-02 | Tampering / Destruction | save_image_optimized output location | high | mitigate | Originals are never overwritten: the batch loop always writes into a `cleaned/` subdir (Plan 03 enforces `output_dir.name == "cleaned"`); Export goes through a Save-As dialog the user confirms. The writer writes only to `path` it is handed; it does not write to `original.parent`. |
| T-02-03 | Tampering | save_image_optimized original-metadata read | low | mitigate | The `Image.open(original)` call is wrapped in `try/except (OSError, ValueError): pass` so a malformed original cannot crash the writer — the page simply saves without metadata preservation. |
| T-02-SC | Tampering | package installs | low | accept | Phase 2 installs NO new packages (RESEARCH §Package Legitimacy Audit — Pillow, NumPy, opencv are the Phase 1 runtime, all `[VERIFIED: pyproject.toml]`). No `[ASSUMED]`/`[SUS]` install occurs; no blocking checkpoint needed. |
