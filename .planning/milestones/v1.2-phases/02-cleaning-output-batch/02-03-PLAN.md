## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker thread ↔ ImageFile.mask | The batch task fn writes page.mask on the worker thread; the GUI thread also writes it via on_page_selected (Plan 02). Concurrent access is the Open-Question-Q2 race. |
| batch loop ↔ filesystem | Every page write crosses into cleaned/; a path-derivation bug could write outside the source folder. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | batch output location (D-07) | high | mitigate | The output dir is DERIVED (`source.parent / "cleaned"`, D-06) and is never user-supplied, removing the traversal vector. Defense-in-depth: `_run_batch_task` asserts `cleaned_dir.name == "cleaned"` at entry and raises ValueError otherwise, so the writer can never write to source.parent directly. test_output_to_cleaned_subdir verifies outputs land only in cleaned/. |
| T-02-02 | Tampering / Destruction | original files | high | mitigate | The loop only ever writes to `cleaned_dir / page.path.name`; it never writes to `page.path` or `page.path.parent`. The D-03 passthrough uses `passthrough_original` which writes to `cleaned_dir / original.name` (Plan 01), never over the original. Originals are read-only inputs. |
| T-02-05 | Tampering / DoS | concurrent write/write on ImageFile.mask (Q2 race) | medium | mitigate | Plan 04 disables page-switch while `_op_running` for a batch (D-08 blocks the editor), so on_page_selected cannot fire during the run. Until Plan 04 lands, the batch loop is not wired to any UI trigger, so the race window is closed by ordering. |
| T-02-06 | DoS | half-written output on cancel (Pitfall 4) | high | mitigate | The abort check is ONLY at the loop top, before any per-page read/detect/inpaint/save begins. Once a page's work starts it runs to completion; a canceled page is simply not started. test_abort_between_pages asserts page-1 output exists and page-2 output does not. |
| T-02-07 | Availability | per-page failure crashes the batch (D-04) | medium | mitigate | Every per-page body is wrapped in try/except that logs to loguru and appends to `failed[]`, then continues. test_per_page_failure_continues verifies one bad page does not stop the others. |
| T-02-08 | DoS | model re-load per page (Pitfall 3) | medium | mitigate | Models load ONCE in the entry-point wrapper before `_run_batch_task`; the loop body never calls `.load`. test_model_loaded_once asserts each fake's load_calls == 1 for a 3-page batch. Reuses `_resolve_*_model_path` cache short-circuits (CR-10/CR-11). |
| T-02-SC | Tampering | package installs | low | accept | No new packages (Phase 1 runtime reused). No install checkpoint. |
