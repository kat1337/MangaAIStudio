<objective>
Implement per-page mask persistence (D-11) — the central data-model change that makes the two-stage batch workflow possible. Phase 1's canvas holds one mask for the *current* page in `EditorCanvas._mask`, and `MainWindow.on_page_selected → reset_history` discards canvas state on every page switch. This plan lifts mask state onto `ImageFile.mask` (whose slot already exists at `core/image_file.py:69` but is unused for persistence) and saves/restores it at the `on_page_selected` boundary so that Batch Detect (Plan 03) can store one mask per page and Batch Clean (Plan 03) can read them all back.

This is the load-bearing dependency of the phase: it MUST land before Plan 03 (batch runner). Per RESEARCH §Pitfall 1, without this a Batch Detect over 30 pages has nowhere to store 30 masks.

Purpose: Make masks survive page navigation so the detect → review → clean workflow is possible (D-01, D-02).

Output: `core/image_file.py` (modified, add `has_mask_content`), `gui/main_window.py` (modified `on_page_selected` + `_last_page_index` field), `tests/test_gui_batch.py` (new GUI tests).
</objective>
